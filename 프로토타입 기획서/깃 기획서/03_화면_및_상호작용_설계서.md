# wayMate 화면 및 상호작용 설계서

작성일 2026년 11월 11일 · 버전 0.6 · 팀 공유용 수정안

모바일에서 내 에이전트와 대화하며 나와 여행을 준비하고, 차량에서 원하는 방식으로 상대를 알아간다. 에이전트의 장소 제안으로 잠깐 만난 뒤에는 사람과 함께하거나 내 캐릭터와 여행을 이어간다. 이 문서는 이를 구현할 **화면 구성, 버튼의 활성 조건, 실행 결과, 취소·실패·재진입 분기**를 정한다.

기준은 [01. 목업 기획 및 범위 정의서 v0.6](01_목업_기획_범위_정의서.md)와 [02. 시연 시나리오 및 대본 v0.6](02_시연_시나리오_및_대본.md)다. 대사·인물·일정은 02번을 사용한다. 이번 문서는 동작 설계이며 실제 UI·통신·SDK 구현 완료를 뜻하지 않는다. 코드 구성과 데이터 형식은 04번, 담당과 실제 검수 결과는 05번에서 정한다.

## 1. 설계 기준과 표기

- **대화가 준비의 중심이다.** 성향 설문을 한 장의 입력 폼으로 제시하지 않는다. 에이전트의 질문, 사용자의 자유 입력, 요약·수정, 소개 미리보기와 공개 확인을 같은 대화 안에서 이어간다. 예시 칩은 전송하지 않는 초안 보조다.
- **내 친구는 계속 남는다.** 연결 전·콘텐츠 이용 중·연결 종료 뒤에도 내 에이전트와 본인의 여행 정보를 유지한다. 상대 연결이 없다는 이유만으로 내 친구와의 여행을 막지 않는다.
- **차량 콘텐츠는 선택한다.** 상대 캐릭터 대화, 말 전달, 직접 통화, 추가 MC 통화는 목록에서 고른다. 모두 완료해야 만남으로 갈 수 있게 만들지 않는다.
- **발화의 출처를 구분한다.** 공개 프로필을 바탕으로 한 캐릭터 답변, 실제 사용자 메시지의 재현, 통화·만남 샘플을 이름·설명·자막으로 구분한다. 색이나 입 모양만으로 구분하지 않는다.
- **행동마다 확인한다.** 공개 승인, 연결, 메시지 전송, 통화, MC 참여, 만남, 내비 반영, 최종 동행의 확인·동의를 서로 대신하지 않는다.
- **취소와 이동 처리를 구분한다.** 만남을 취소해도 이미 추가한 경유지가 자동으로 사라졌다고 표시하지 않는다. 경유지 제거 승인·처리·결과를 별도로 보여준다.
- **두 결말을 동등하게 다룬다.** 최종 선택 두 개는 같은 크기와 강조 수준을 사용한다. 내 캐릭터와 이어가는 결말에는 친구 대화와 다음 활동을 제공한다.
- **범위를 정직하게 표시한다.** 실제 SDK 결과, 시연 음성, 이동 경험 개념 시연, 모의 내비 표시는 발표용 상태 영역에 둔다. 사용자의 대사에는 내부 구현 설명을 섞지 않는다.

화면 ID는 `M`이 모바일 웹, `P`가 Pleos 차량 앱, `O`가 시연자 패널이다. `S`는 02번의 장면, `DM`은 01번의 기능 ID다. `P02.LIST` 같은 표기는 화면 안의 상태 이름이며 새로운 화면이나 확정된 코드/API 이름이 아니다.

## 2. 화면 목록과 이동 구조

기본 사용자 화면은 **모바일 4개·차량 4개**다. 같은 화면에서 상태와 내용 영역을 교체한다. 후기 P05와 MC 통화 상태는 추가 범위이고 O01은 별도 시연자 패널이다.

| 화면 ID | 화면과 주요 상태 | 장면·기능 |
|---|---|---|
| M01 | 대화형 온보딩, 별명·외형, 프로필 요약·수정, 공개 소개·승인 | S01 · DM01 |
| M02 | 여행 희망 대화, 대표 계획 확인·저장, 본인 여행과 내 친구 | S02 및 연결 없는 여정 · DM02·DM04 |
| M03 | 자동 추천 준비·목록, B 상세, C·D 요약 | S03 · DM03 |
| M04 | 연결 요청·시간 확인·연결 완료, 차량 전달 준비·확인 | S04·웹 S05 · DM04·DM05 |
| P01 | 여행 불러오기, 준비 안 됨·실패, 상대 연결 또는 본인 여행으로 진입 | 차량 S05 · DM05 |
| P02 | 콘텐츠 목록, 상대 캐릭터, 말 전달, 일반 통화, 추가 MC, 내 에이전트 | S06·S07·S08·S08-MC · DM06·DM07 |
| P03 | 장소 제안·합의, 내비 추가·취소·제거, 도착·만남 재연 | S09·S10 · DM08·DM11 |
| P04 | 최종 선택·상대 대기, 두 결말, 만남 전 종료와 본인 여정 | S11·S12-A·S12-B 및 조기 종료 · DM09·DM04·DM08 |
| P05 추가 | 여행 후 기록, 장식 미리보기·적용·종료 | S13 · DM10 |
| O01 | B 응답·시간 전환·모의 진행, 제한 확인, 초기화·결말 재시연 | 전체 · DM11 |

대표 흐름은 **M01 → M02 → M03 → M04 → P01 → P02 → P03 → P04**다. 단, 아래 분기는 함께 제공한다.

| 출발과 조건 | 도착·동작 |
|---|---|
| M01에서 공개를 보류 | M02 본인 여행 모드. 후보 연결은 잠그되 내 에이전트와 여행 준비는 유지 |
| M04에서 요청 거절·취소·연결 종료 | M02 본인 여행 모드. 상대 연결 없이 차량 전달도 준비 가능 |
| P01에서 본인 여행만 불러오기 | P02 내 에이전트 상태. 상대 콘텐츠·만남은 제공하지 않음 |
| P02에서 콘텐츠 종료·건너뛰기 | P02 목록. 연결·본인 일정 유지 |
| P02에서 지금은 쉬기 | P02 휴식 상태. 미전송 문장이나 통화를 자동 실행하지 않음 |
| P02에서 만남 제안 받기 | 조건 확인 후 P03. 특정 콘텐츠 완료는 요구하지 않음 |
| P02·P03에서 연결 종료·만남 취소 | P04 만남 전 종료형. 최종 동행 선택을 만들지 않음 |
| P03에서 만남 종료 이벤트 | P04 최종 선택. 도착이나 내비 성공만으로는 진입하지 않음 |
| P04에서 양쪽 함께 | P04 함께 결말. 추가 후기는 O01에서 P05로 전환 |
| P04에서 한쪽이라도 각자 | P04 내 캐릭터 결말. 상대 연결은 종료 |

만남 전 종료형과 만남 뒤 내 캐릭터 결말은 같은 P04를 쓰지만 대사와 진입 조건은 다르다. 실제로 만나지 않았는데 ‘이번 만남은 여기서 마무리해요’나 만남 후 최종 선택을 보여주지 않는다.

## 3. 모든 화면에 적용할 상태 규칙

### 3.1. 별도로 유지할 상태

프로필·공개 승인, 여행 계획, 상대 연결, 콘텐츠, 메시지 요청, 통화·MC, 만남, 내비 요청, 최종 선택, 시연 회차를 구분한다. 예를 들어 통화가 거절되어도 연결은 유지되고, 만남이 취소되어도 내비 경유지 정리는 남을 수 있다. 하나의 ‘매칭 완료’ 표시로 합치지 않는다.

| 확정할 행동 | 실행·확정 조건 | 앞선 행동이 대신하지 못하는 것 |
|---|---|---|
| 공개 프로필 준비 | 본인 정보 확인 후 공개 항목·소개 승인 저장 | 채팅 답변 자체는 공개 동의가 아님 |
| 대화 연결 | A 요청 + 현재 요청에 대한 B 수락 + A 공통 시간 확인 | 후보 추천은 연결이 아님 |
| 메시지 전달 | 보낼 문장 확인 + 전송 성공 | 캐릭터에게 한 질문을 자동 전달하지 않음 |
| 일반 통화 | 현재 통화 요청에 대한 A·B 동의 | 대화 연결은 통화 동의가 아님 |
| MC 참여 | 일반 통화 동의 + A·B의 별도 MC 참여 동의 | 일반 통화 동의는 MC 동의가 아님 |
| 만남 확정 | 동일 장소·시각·체류시간에 대한 양쪽 동의 | 메시지의 긍정적 답변이나 통화 내용은 만남 확정이 아님 |
| 내비 추가 | 유효한 만남 확정 + 주차 상태의 운전자 승인 | 만남 확정만으로 내비를 바꾸지 않음 |
| 경유지 제거 | 제거 대상 확인 + 주차 상태의 운전자 승인 + 처리 결과 확인 | 만남 취소는 제거 성공이 아님 |
| 최종 동행 | 만남 종료 + 현재 선택에서 양쪽 함께 | 통화·만남 동의를 재사용하지 않음 |

### 3.2. 저장·대기·실패·재진입

| 상황 | 공통 UI·동작 |
|---|---|
| 선택·필수 확인 전 | 실행 버튼을 잠그고 필요한 선택을 가까이에 안내. 선택 상태를 테두리·체크·문자로도 표시 |
| 저장·불러오기·전송 중 | 즉시 처리 중 표시. 같은 요청의 중복 실행은 잠금. 허용된 취소·중단까지 일괄 비활성화하지 않음 |
| 상대 응답 대기 | 요청 대상과 대기 항목·취소 동작 표시. 기다린 시간만으로 수락·거절을 생성하지 않음 |
| 명시적 실패 | 입력·선택·요청 맥락을 유지하고 실패 안내와 적합한 재시도 제공. 완료 화면으로 대체하지 않음 |
| 결과 미확인 | 실패나 성공으로 단정하지 않음. 상태 확인을 우선하고 중복 실행 위험이 있는 재시도는 잠금 |
| 재시도 | 이전 요청의 취소·실패·처리 여부를 확인. 새 요청에 이전 응답을 적용하지 않음 |
| 브라우저 뒤로 가기·앱 재진입 | 현재 유효한 상태를 복원. 화면 재표시만으로 전송·동의·내비 요청·음성 재생을 반복하지 않음 |
| 오래된 정보 | ‘새 정보가 있어요. 다시 불러와 주세요’와 새로 불러오기 제공. 오래된 동의로 다음 행동을 열지 않음 |
| 취소·종료 후 늦은 응답 | 이전 요청·회차 응답은 무시. 이미 끝난 연결·만남·결말을 되살리지 않음 |

요청 시작 전에는 이전 준비 화면으로 돌아갈 수 있다. 요청 이후에는 단계를 거꾸로 밟는 버튼 대신 해당 요청의 취소·연결 종료를 제공한다. 실제 저장·동기화·복원 방법은 04번에서 정한다.

생성 응답이 유실되어 requestId를 모를 때에도 지원되는 취소 버튼은 원래 commandId의 취소로 연결한다. 메시지가 이미 저장·전송됐다면 ‘이미 보냈어요’와 현재 대화를 보여주고 회수됐다고 표시하지 않는다. 취소할 수 없는 작업은 확인 중 안내를 유지한다.

상대 연결 종료가 확인되면 상대 콘텐츠·통화 샘플·MC 재생을 중단하고 대기 요청을 무효화한다. 종료 안내 뒤에는 내 에이전트와 본인 여정을 유지한다. 화면을 다시 열어도 이전 상대 콘텐츠를 자동 재개하지 않는다.

### 3.3. 공개 정보와 변경값

- 본인 원문 채팅·상세 일정과 상대에게 전달할 프로필을 분리한다. 상대 소개에는 승인한 정보·표현만 사용한다.
- M01에서 지원값·표현·공개 항목을 바꾸면 소개를 다시 만들고 공개 승인을 다시 확인한다. 변경 전 승인을 새 소개에 자동 적용하지 않는다.
- 요청 전 프로필을 수정하면 M03의 추천 설명도 현재 공개값으로 갱신한다. 비공개로 바꾼 항목을 상대 차의 소개나 공통 취향 설명에 다시 넣지 않는다.
- 요청 이후 프로필·여행 재설정과 새 연결은 O01 전체 초기화로 시작한다. 거절·취소·종료 뒤의 본인 여행 조회·대화는 유지하되 같은 회차의 새 상대 요청은 열지 않는다. 최종 선택 재시연은 결말만 복원한다.
- 별명·외형·표현 프리셋은 웹·차량·결말에 같은 값을 쓴다. A의 별명을 녹음에 고정하지 않고, 한국어 조사 때문에 잘못된 문장이 생기지 않게 문구를 구성한다.

공개 철회는 상대 연결을 끝낸 뒤 M02 본인 여행의 ‘소개 공개 철회’로 제공한다. 현재 공개를 private로 바꾸되 본인 요약·내 친구는 유지한다. 새 소개 작성·재공개·새 상대 요청은 전체 초기화로 하며, 이미 직접 보낸 사용자 메시지를 회수한 것으로 표시하지 않는다.

## 4. 모바일 웹 화면 상세

### 4.1. M01 대화형 온보딩·프로필·공개 소개

**구성:** 상단 서비스명과 ‘내 친구와 알아가기’, 중앙 에이전트와 채팅 기록, 하단 고정 자유 입력창·전송 버튼을 배치한다. 선택 사항인 예시 칩은 입력창 위에 작게 둔다. 한 번에 한 질문만 답하게 하고 이미 보낸 답변은 말풍선으로 남긴다. 별명·외형·요약·공개 범위는 채팅에 연결된 카드 또는 펼침 패널로 제공한다.

02번 S01의 5차례 문답을 기준으로 한다. 질문 1~4의 자유 입력·수정·전송은 필수다. 질문 5는 별명 입력·외형 2개 중 선택이다. 처음 입력창은 비워두고 키보드 입력을 기본으로 제공한다. 예시를 누르면 초안만 채우며 수정/삭제·예시 없이 전송이 가능하다. 전송은 공백만인 입력/500 Unicode 코드 포인트 초과/저장 중일 때 잠근다. 실패 시 초안과 원문을 유지하고 같은 명령으로 재시도한다. Enter는 줄바꿈, 전송은 명시 버튼으로 구분한다. 자동 성향 분석·실제 음성 특징 추정은 하지 않는다.

| 상태 | 표시·버튼 | 활성 조건·실행 결과 |
|---|---|---|
| M01.START | ‘데모로 시작하기’ | 실제 가입·인증 없이 대화 시작 |
| M01.CHAT | 질문 1~4, 채팅 기록, 빈 자유 입력창, 선택적 예시 칩, ‘이 답변 보내기’ | 유효한 직접 입력이면 전송 활성. 예시는 초안만 채움. 저장 성공 후 원문 말풍선과 다음 준비 질문. 전송 중 중복 잠금 |
| M01.CHARACTER | 질문 5, 별명, 외형 2개, ‘이 모습으로’ | 유효한 별명·외형 확인 후 요약. 변경값을 캐릭터에 즉시 반영 |
| M01.SUMMARY | 내가 쓴 답변, 소개 예시·지원값 확인, ‘이 소개값 확인’, ‘수정’, ‘이 소개값은 쓰지 않을래’ | 원문과 시연 소개값을 분리. 본인이 확인한 값만 profile에 저장. 미확인값을 비워두고 최소 소개/본인 여행 가능 |
| M01.PUBLIC_REVIEW | 소개 미리보기·공개 항목, ‘이 소개로 시작하기’, ‘지금은 나만 보기’ | 소개 승인 저장 성공은 M02 기본 모드. 나만 보기는 본인 확인값만 저장하고 M02 본인 여행 모드 |
| M01.SAVING | ‘소개를 저장하고 있어요’ | 중복 저장 잠금. 성공 전 공개 완료·다음 단계로 표시하지 않음 |

별명은 기본값 ‘파도’, 앞뒤 공백을 제거한 1~10자를 허용한다. 빈 값·길이 초과·줄바꿈은 입력 아래에 이유를 표시하고 ‘이 모습으로’를 잠근다. 문자 길이 계산과 저장 검증은 04번에서 통일한다.

자유 답변의 내용은 대표 조건으로 제한하지 않는다. 별도 소개 카드에서 확인할 구조화 시연값은 바다 산책·카페, 여유로운 여행, 조용한 대화다. 입력을 자동 매핑하거나 예시 답변으로 교체하지 않는다. 표현은 ‘차분하게’와 ‘가벼운 농담도 조금’ 중 선택할 수 있게 한다. 차분한 표현을 선택하면 소개·차량·내 캐릭터 결말에서 가벼운 웃음 표현을 제거한 대본을 사용한다. 입력과 무관하게 같은 성격을 자동 추정한 것처럼 표시하지 않는다.

공개 미리보기에는 별명·캐릭터와 선택한 관심사·여행 및 대화 스타일·소개 표현을 보여준다. 원문 대화는 포함하지 않는다. 연결할 최소 소개에는 별명·캐릭터 확인이 필요하며 나머지는 선택이다. 선택 항목을 제외해도 최소 소개를 승인했다면 여행 요약 공개 확인으로 이어갈 수 있다. 전체 공개 보류는 본인 여행 모드이며, 아직 연결 요청 전이면 ‘공개 소개 확인하기’로 재확인할 수 있다. 소개·추천·대화는 02번 2.3절의 변형을 사용한다.

### 4.2. M02 여행 희망·계획 확인·본인 여행

**구성:** 내 에이전트와 여행 희망을 나누는 채팅, 여행 요약 카드, 본인 전용 ‘내 다음 일정’, 하단 저장 동작을 둔다. 정확한 날짜·시각은 자연어 대사 옆의 확인 카드로 보여준다.

대표 값은 2026년 11월 14일 강릉 해변권, 만남 가능 시간 13:00~15:00, 기존 다음 일정 도착 15:20·내 숙소 도착 예상 15:45·내 숙소 도착 마감 16:00이다. 채팅에서 준비된 여행 희망을 선택하고 프리셋을 확인·저장한다. 달력·지도 검색·자유 일정 수정처럼 보이는 조작은 넣지 않는다.

일정 카드의 라벨은 위 표현으로 통일한다. M02·M03·M04에서 ‘만남 가능 시간/공통 가능 시간’은 약속을 잡을 수 있는 범위로, P03의 ‘첫 만남 14:15~14:35 · 20분’은 실제 합의한 약속으로 표시한다. P03·P04의 본인 카드에서도 ‘기존 다음 일정 도착’과 ‘내 숙소 도착 예상/마감’을 분리한다. 숙소와 개인 방문지의 상세는 상대 카드에 넣지 않는다.

M02에서는 만남 장소·약속 시각을 미정으로 두고 미래의 대표 시연값을 미리 확정 표시하지 않는다. P03도 제안 중에는 ‘제안한 시간’, 양쪽 수락 후에만 ‘확정된 첫 만남’으로 표시한다.

본인 일정과 분리해 ‘상대에게 보일 여행 요약’ 카드에 날짜·권역·가능 시간만 표시한다. ‘이 여행 요약을 후보에게 공개’는 미선택에서 시작하며, 선택 여부를 저장한다. 저장 자체가 공유 동의는 아니다. 소개와 여행 요약이 모두 승인돼야 후보 제안·연결을 연다. 다음 방문·복귀 계획은 이 공유 항목에 포함하지 않는다.

| 상태 | 표시·버튼 | 실행 결과·분기 |
|---|---|---|
| M02.CHAT | 여행 희망·가능 시간 답변, ‘계획 확인하기’ | 답변 확인 뒤 대표 계획 카드 표시 |

연결 거절·취소로 돌아온 본인 여행 모드에서는 ‘이번 연결은 여기서 마무리할게. 네 여행은 나랑 이어갈 수 있어’라는 안내와 현재 일정의 다음 활동을 보여준다. 자동으로 다시 후보를 요청하지 않는다. 대표 시연의 재시작은 O01에서 한다.

본인 여행의 차량 전달은 내 친구를 이어가는 기능이다. 상대 연결·만남 동의가 생긴 것으로 처리하지 않는다. 저장된 프로필·계획이 유효하지 않으면 해당 준비 단계로 돌아가게 한다.

취소·종료는 저장 성공을 확인한 뒤 반영한다. 취소가 성공하면 늦은 B 수락이나 차량의 이전 전달본으로 연결을 되살리지 않는다. 차량이 읽기 전 연결을 종료한 경우에는 본인 여행 모드로 다시 준비할 수 있다. 다른 채널에서 온 최신 취소·종료 기록은 화면 복귀 시 우선 확인한다.

차량에서 연결 종료가 확인되면 웹도 M02 본인 여행으로 이어갈 수 있다. 이번 회차가 이미 연결을 요청한 상태라면 공개 확인으로 M03을 다시 열지 않고 새 연결은 전체 초기화가 필요하다고 안내한다.

## 5. Pleos 차량 화면 상세

### 5.1. 공통 배치

앱 상단에는 서비스명·현재 단계·연결된 상대를 짧게 표시한다. 넓은 창은 캐릭터·발화자 영역과 대화·카드 영역의 2열, 좁은 창은 캐릭터 요약 위·내용 아래로 재배치한다. 공통 동작은 현재 내용 가까이에 놓고 가려지지 않게 한다.

상태 표시줄·기어·속도·시계·공조·시스템 내비 UI는 앱 안에 복제하지 않는다. 앱 창은 다른 시스템 UI에 가려질 수 있으며 가로·세로 형태에 대응해야 한다. [공식 Display Layout](https://document.pleos.ai/docs/connect/guide/docs-design/getting-started/layout)

실제 주행 중 기능 허용을 전제로 화면을 만들지 않는다. 이번 목업의 선택·전송·승인은 주차 상태에서만 조작하며 이동 경험은 대본으로 설명한다. 실제 제한은 7절을 따른다.

### 5.6. P02 일반 통화와 추가 MC · S08·S08-MC

| 상태 | 표시·버튼 | 실행 결과·분기 |

MC로 처음 진입해도 일반 통화에 필요한 양쪽 동의를 먼저 확인한다. 이미 일반 통화 중에 MC를 초대하는 경우에는 통화를 유지하면서 별도 MC 동의를 받는다. MC 요청을 거절·취소하면 현재 일반 통화의 동의까지 철회된 것으로 처리하지 않는다.

대기 중 다른 콘텐츠로 이동하려면 ‘제안 취소 후 목록으로’를 사용한다. 실제 통화 중에는 ‘통화 종료 후 목록으로’를 사용한다. 종료·취소는 항상 명확하게 접근할 수 있게 하고, 늦은 동의로 재생을 다시 시작하지 않는다. MC가 없는 빌드에서는 실행 버튼을 숨기거나 ‘준비 중’의 비실행 카드로 표시한다. 실제 마이크·전화번호 입력·실시간 통신 UI는 추가하지 않는다.

여기서 active는 동의한 샘플 통화 세션이며 음성이 계속 재생 중이라는 뜻은 아니다. 앱 숨김·포커스 상실 후에는 ‘샘플 일시중단’과 정차 확인 후 ‘현재 문장 다시 듣기’·‘통화 종료’를 보여준다. 샘플 종료·일시중단만으로 동의나 실제 통신 종료를 추정하지 않는다. 콘텐츠를 건너뛰었을 때는 02번의 일반 인사 대사를 사용한다.

### 5.7. P03 만남 장소 제안·합의 · S09

**구성:** 에이전트의 추천 이유, 가상 장소 이미지, 만남 날짜·시각·체류시간, 이동 부담·양쪽 일정 충족 요약, 본인 전용 다음 일정, 제안·취소 동작이다.

고정값은 바다쉼표 카페, 11월 14일 첫 만남 14:15~14:35 · 20분, A·B 도착 예정 14:02·14:10·차이 8분, A 추가 주행 7분이다. 도착과 만남 시작을 구분하고 먼저 도착하면 기다리는 설정임을 설명한다. 양쪽 일정은 충족한다는 요약으로 보여준다. A의 본인 카드에만 기존 다음 일정 도착 15:20·내 숙소 도착 예상 15:45·내 숙소 도착 마감 16:00을 표시한다. B의 추가 5분·숙소 도착 예상 15:40·마감 16:00은 일정 검수 데이터로 두고 B의 전체 일정은 공개하지 않는다.

장소 카드에는 ‘추가 주행 7분 / 도착 후 대기 약 13분 / 첫 만남 20분’을 함께 보여주고, ‘이후 산책 20분은 만남 후 별도 선택’으로 분리한다. 추가 주행만을 전체 소요시간처럼 강조하지 않는다. 이 숫자도 고정 시연값이며 실제 지연·영업 대기를 계산한 결과는 아니다.

가상 장소·시연 일정이라는 설명은 카드에 가까이 두고, 실제 영업·주차 검수 완료나 실시간 교통 계산 결과로 표현하지 않는다. 자유 장소·시간 편집은 없다.

### 5.8. P03 내비 추가·취소·경유지 제거 · S10

기존 목적지가 없거나 준비한 기준과 다르면 추가 버튼을 잠그고 ‘기존 목적지를 먼저 확인해 주세요’를 표시한다. 내비에서 기존 목적지를 준비하는 절차는 04번의 시험 조건을 따르며, 앱이 임의의 목적지로 덮어쓰지 않는다.

실제 모드는 SDK의 기준 목적지 관측을, 모의 모드는 별도 mockRoute에 준비한 가상 목적지를 확인한다. 모의 목적지 확인으로 실제 내비 상태·검증 완료 표시를 갱신하지 않는다.

전체 초기화의 경유지 정리는 ‘만남 취소’와 별도 사유다. 만남이 완료됐거나 취소되지 않았어도 현재 resetId에 속한 자기 경유지 제거 확인을 제공한다. 제거 승인만 정차 상태에서 허용하고 일반 대화·추가·시간 전환 잠금은 유지한다. 차량 앱을 다시 실행해도 같은 deviceId의 정리 상태를 복원한다.

실제 모드에서 응답 미확인인 채 O01로 성공을 만들거나 모의 진행으로 덮지 않는다. 모의 모드는 회차 시작 전에 선택하거나, 실제 실패가 확인된 뒤 시연자가 명시적으로 선택한다. 실제·모의 모두 동의·승인 조건을 지킨다.

### 5.10. P04 최종 선택과 두 가지 여행

**구성:** 선택 전에는 내 에이전트 질문·남은 활동·본인 일정, 선택 뒤에는 해당 결말의 캐릭터·대화·다음 활동을 보여준다. 상대와 내 친구의 등장 비중은 결말에 맞춰 바꾸되, 내 친구를 처음 생긴 보상처럼 표현하지 않는다.

함께 결말에서는 02번 S12-A의 A/B 산책 대사를 재연으로 표시한다. 두 사람이 계속 통화하거나 실제로 위치를 공유한다고 오해할 표시를 넣지 않는다.

첫 진입과 최종 재시연 모두 A 선택 전에는 B 대기 표시·O01 B 선택을 열지 않는다. A가 즉시 내 캐릭터와 이어가기를 선택하면 B 요청 없이 결과로 이동한다. 선택 ID가 준비되지 않았으면 서버 상태를 다시 확인하며 임의 ID·이전 round로 버튼을 실행하지 않는다.

normal 모드에서 결과 대기 중 연결을 끝내면 활성 B 요청을 닫고 P04.CHOICE로 돌아간다. 완료된 만남·선택 ID/round는 유지하고 ‘상대 연결을 마무리했어요’와 내 친구 선택을 제공하며 함께 버튼은 잠근다. 현재 선택은 다시 확인하고 이전 선택은 이력으로 보존한다. 이미 확정된 결말은 바꾸지 않으며 final_replay의 닫힌 live 연결은 별도 checkpoint 규칙을 따른다.

내 캐릭터 결말은 ‘각자의 여행’ 안내 후 내 에이전트가 “이제 네 여행은 어떻게 이어가고 싶어?”라고 묻는다. A의 ‘바다 보면서 좀 쉬고 싶어’와 ‘사진도 한 장 남기고 싶어’ 답변을 선택해 02번 S12-B의 친구 대화로 이어간다. 다음 활동 카드에 해변에서 쉬기·14:55 다음 일정 준비·15:20 다음 방문을 보여준다.

대화·음성을 모두 끝내야 종료할 수 있게 하지 않는다. ‘오늘은 여기까지’는 이유 입력 없이 사용할 수 있다. 다만 제작 완료 검수에서는 친구 대화와 다음 활동이 실제로 제공되는지 확인한다. ‘내 캐릭터와 계속하기’는 준비된 다음 대화·활동으로 이어지며 자유 생성형 채팅 입력을 새로 추가하지 않는다.

A가 함께를 원했는데 B가 각자를 선택한 경우에도 A가 혼자 있고 싶어 했다고 단정하지 않는다. 상대의 이유·평가를 노출하지 않는다. 선택적인 ‘이유 남기기’는 추가 구현할 때만 A 본인이 각자를 선택한 경우에 제공하고, 생략 가능·상대 비공개로 처리한다.

만남 전 종료에서는 S12-B의 만남 완료 대사를 재사용하지 않는다. ‘지금은 어떤 여행을 이어가고 싶어?’와 본인 활동으로 이어가며 이야기 속 시각을 14:35로 자동 바꾸지 않는다. 내비 정리가 남아 있다면 해당 안내가 함께 남는다.

### 5.11. P05 여행 후 기록·장식 · 추가

O01의 ‘여행 종료 후’로 함께 결말에서만 진입한다. 샘플 기록, 현재 외형의 장식 적용 전후, ‘내 캐릭터에 반영하기’, ‘건너뛰기’를 배치한다. 02번 S13 대사를 사용한다.

반영 중에는 중복 클릭을 잠그고 성공 후 선택한 외형에 바다 산책 장식을 한 번 적용한다. 실패 시 적용 완료로 표시하지 않고 재시도·건너뛰기를 제공한다. 건너뛰기는 외형 변경 없이 종료한다. 상대 평가 기반 자동 변경·장기 기억 시스템으로 설명하지 않는다. P05가 없는 빌드에서도 두 기본 결말은 완주할 수 있어야 한다.

## 6. O01 시연자 제어 패널

시연 PC의 별도 관리 화면이다. 사용자 앱의 행동 버튼에 B 수락·만남 종료·초기화를 섞지 않는다. 상단에 회차·장면·현재 대기 요청·내비 실제/모의 모드·실제 제한/시연 제한·미정리 내비 상태를 표시한다. 현재 유효한 이벤트만 활성화하고 잠긴 항목에는 이유를 보여준다.

| 제어 | 활성 조건 | 실행 결과·주의 |

| B 함께 / 각자 | P04에서 A 함께·현재 round의 활성 B requestId 있음 | 앞선 수락 재사용 없음. A 미선택·즉시 각자·요청 종료 뒤에는 잠금 |

목록이나 다른 콘텐츠를 보고 있어도 유효한 메시지 대기 요청은 남을 수 있다. 이때 답변 이벤트는 새 답장 표시만 갱신하고 자동으로 화면·음성을 전환하지 않는다. 종료·취소·이전 회차 이벤트는 다시 활성화하지 않는다.

이번 목업의 만남 취소 검수는 제안부터 만남 재연 시작 전까지다. 만남 재연 이후에는 02번 S10의 만남 종료와 S11의 여행 선택으로 이어간다. 재연 시작·종료는 시연자가 진행하며 실제 만남 시간을 감지하는 기능이 아니다.

**최종 선택 재시연:** 본인·B 최종 선택, 최종 대기 응답, 이후 이유·후기·장식 변경만 지운다. 앞선 프로필·공개 승인·연결·만남 완료는 같은 이야기의 전제로 유지하고 내비를 다시 요청하지 않는다. 이전 결말의 늦은 B 응답은 같은 화면이어도 무시한다. 만남 전 종료형에서는 사용할 수 없다.

서버가 새 finalId·round와 requestId=null인 A 선택 상태를 반환하면 P04.CHOICE로 간다. A가 함께를 다시 고른 뒤에만 새 B 요청과 O01 응답을 연다. 이전 B 요청을 새 round에 연결하지 않는다.

재시연 중에는 P04의 최종 선택·해당 B 응답·결말만 허용한다. 표시용 이야기 맥락을 열어도 닫힌 실제 연결·철회한 공개 승인을 되살리지 않는다. P02·P03의 새 메시지·통화·만남·SDK 추가를 다시 열지 않으며, 현재 내비·제한·복구 상태도 checkpoint의 과거 값으로 덮어쓰지 않는다. 필요한 관리·중단·정리는 04번의 제한된 예외를 따른다.

추가 이유·후기를 채택했다면 새 round의 확정 결말에서 원래 조건을 만족할 때만 이유 저장·여행 후 전환·장식 반영/건너뛰기도 허용한다. 이전 round의 입력·장식 반영 요청은 재사용하지 않는다.

**처음부터 시작:** 확인 패널에 초기화 범위를 안내한다. 웹·서버·차량의 온보딩·공개 승인·계획·연결·콘텐츠·대기 요청·최종 선택·추가 장식과 예약 이벤트를 정리한다. 실제 내비 상태는 별도 시험 정리 절차로 확인한다. 한 부분이라도 미완료면 ‘초기화 확인 필요’와 미완료 항목을 표시하고 새 실제 연동 시연을 시작하지 않는다.

주행 제한 중에는 B 대화 응답·새 동의·시간 전환·결말 재시연으로 사용자 흐름을 진행하지 않는다. 초기화나 외부 경로 정리가 주차·확인을 요구하면 그 단계에서 대기하며 제한을 우회하지 않는다. O01은 사용자 동의를 대신하는 도구가 아니다.

## 7. 주행 제한·음성·백그라운드 처리

### 7.1. 주행 제한 우선순위

실제 플랫폼 제한이 시연용 상태보다 우선한다. 실제 제한이 없더라도 시연용 제한을 적용해 잠금 상태를 확인할 수 있다. 상태를 아직 확인하지 못한 경우에는 조작 가능으로 추정하지 않고 ‘차량 상태 확인 중’으로 제한 대상 버튼을 잠근다.

앱은 플랫폼의 `CarUxRestrictions` 상태에 맞춰 제한을 적용한다. 구체적인 연동·지원 범위는 04번에서 검증한다. [공식 주행 규제 개발 가이드](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/driving-restriction-development-guide)

| 상태·상황 | 화면·동작 |
|---|---|
| 주차·제한 없음 확인 | 현재 업무 상태가 허용하는 선택·전송·동의·승인 제공 |
| 주행·시각/업무 조작 제한 | 목록·키보드·메시지 전송·통화 시작·MC 초대·만남 동의·내비 승인·최종 선택 잠금. 검증된 driving_voice는 음성 문답·쉬기·종료만 별도 허용 |
| 음성·통화 중단 | 플랫폼이 허용하는 중단·종료 동작은 유지. 새 통화·동의·전송과 구분하며 제한 해제 전 재생을 자동 재개하지 않음 |
| blocked·앱 표시 허용 | ‘주차 후 이어갈 수 있어요’와 잠긴 이유 표시. 음성 지원 미확인도 여기에 포함. 반복 팝업·애니메이션 없음 |
| 플랫폼이 앱을 가림 | 강제 화면·오버레이로 우회하지 않음. 표시 복귀 시 현재 상태 재확인 |
| 제한 중 도착한 취소·내비 결과 | 취소와 요청 결과를 버리지 않고 기록·대조. 새 동의·자동 경로 변경·다음 장면 진행은 하지 않음 |
| 주차 후 재개 | 현재 연결·제안·요청의 유효성 확인. 미확인 문장을 자동 전송하거나 이전 승인 버튼을 자동 실행하지 않음 |

시연용 B 대화 이벤트는 제한 중 실행하지 않는다. 실제 비동기 내비 결과나 이미 도착한 취소 기록은 사용자 조작과 구분해 상태를 정리한다. 예를 들어 취소 뒤 도착한 내비 성공은 만남 재개가 아니라 경유지 정리 필요 상태다.

**P02.DRIVING_VOICE · WF-051**은 상대 캐릭터와 주행 중 짧게 말하고 듣는 기본 목표 화면이다. `parked / driving_voice / blocked`를 구분하며 조건은 04번 7.3절을 따른다. 발화자와 ‘말하는 중/쉬는 중’ 같은 짧은 상태만 표시하고, 작은 정적 캐릭터도 시각 표시가 허용된 경우만 사용한다. 긴 자막·채팅 기록·목록·게임·반복 애니메이션은 표시하지 않는다. 마이크가 실제 열린 경우에만 ‘듣는 중’을 표시한다. 음성의 쉬기·종료가 장면 종료/연결 취소/메시지 전송을 만들지 않는다.

WF-032는 플랫폼 차단·지원 미확인 화면이고 WF-051은 지원을 검증할 음성 목표 화면이다. DO/카테고리·기능별 실제 제한·마이크/오디오·세션/신선도·foreground·검증 증빙을 충족한 환경만 driving_voice에 진입한다. 현재 목업과 미확인 환경은 blocked를 유지하고 주차/발표에서 음성 목표를 재현한다. 복귀·포커스 획득만으로 녹음·재생·승인을 자동 시작하지 않는다. 실제 주행 중 음성 지원은 별도 검증 항목이며 대본 재생을 통과 증거로 쓰지 않는다. [공식 주행 안전 설계](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline)

| 무음·음성 실패 | 주차에서는 자막·같은 동의 조건으로 진행. driving_voice에서는 짧게 알리고 중단하며 긴 자막·터치 선택으로 대체하지 않음 |
| 앱 백그라운드·복귀 | 현재 상태·요청 결과 확인 후 표시. 이전 녹음의 처음부터 재생이나 전송·승인을 반복하지 않음 |

캐릭터 기본 표현은 정지·말하는 표시·응답 대기의 세 가지로 충분하다. 입 모양 동기화·반복 움직임을 필수로 만들지 않는다. 음성 재생 종료만으로 동의하거나 다음 화면을 열지 않는다.

공식 UI 가이드는 충분한 대비와 짧은 텍스트를 요구하며 아이콘·텍스트·이미지의 대비율 4.5:1 이상을 안내한다. 긴 대사는 의미와 발화자를 유지해 짧은 자막 단위로 나누고, 한 화면에 긴 문단을 쌓지 않는다. [Pleos Connect UI Design Guide](https://document.pleos.ai/docs/connect/guide/docs-design/Introduction/intro)

### 8.2. 공통 컴포넌트와 상호작용

| 컴포넌트 | 담을 내용·동작 |
|---|---|
| 대화 말풍선·발화 라벨 | 본인·내 에이전트·상대 캐릭터·사용자 메시지·MC를 이름으로 구분. 말풍선 색만으로 출처를 구분하지 않음 |
| 온보딩 예시 칩 | 입력창에 수정 가능한 초안만 채움. 예시 없이 직접 입력 가능하며 전송은 별도 버튼 |
| 차량 답변·질문 선택 칩 | 주차 상태에서 선택 표시 + 별도 확인 버튼. 누르는 즉시 전송하지 않음 |
| 공개 소개 카드 | 현재 별명·외형·승인 대상 항목·소개 문구. 공개 제외·수정과 재확인 연결 |
| 여행·본인 일정 카드 | 본인의 계획과 상대에게 보일 요약 구분. 만남 장소와 복귀점 정보 섞지 않음 |
| 추천 카드 | 추천 이유·공통 시간·예상 이동 부담. B 요청과 C·D 요약 기능을 구분 |
| 콘텐츠 카드 | 이용 가능·진행 중·새 답장·준비 중을 문자로 표시. 새 콘텐츠가 이전 동의를 자동 사용하지 않음 |
| 요청·결과 안내 | 요청 대상·현재 처리·취소·재시도·확인 필요를 구분. 오류는 관련 동작 가까이에 유지 |
| 종료·취소 확인 | 무엇이 끝나고 무엇이 유지되는지 간단히 안내. 만남 취소와 경유지 정리는 별개임을 설명 |
| 버튼·초점 | 비활성 이유·선택·처리 중 상태를 문자로 제공. 웹 키보드 순서와 초점 표시, 캐릭터·아이콘의 접근 가능한 이름 제공 |

새 메시지·처리 결과는 읽을 수 있는 상태 안내로 제공하고, 팝업이 입력을 가리거나 초점을 갑자기 가져가지 않게 한다. 패널을 닫으면 원래 버튼으로 초점을 돌린다. 필수 오류·현재 상태를 잠깐 나타났다 사라지는 안내에만 맡기지 않는다.

이미지·음성은 실제 준비한 소재만 사용한다. 정적인 경로 예시는 실제 Navigation 화면이나 상대 현재 위치 추적처럼 표현하지 않는다. 자막을 음성 대본의 기준으로 삼고 별명·표현 변경에 맞지 않는 녹음을 섞지 않는다. 파일 포맷·용량·경로·재생 제어·상태 저장은 04번에서 정한다.

화면이 같은 데이터를 참조하도록 공개 프로필, 본인 일정, 상대 공개 정보, 요청·동의, 만남 제안, 내비 결과, 최종 선택을 연결한다. 여기의 상태 이름을 그대로 API로 고정하지 않으며, 실제 통신·버전·미처리 응답 처리는 04번에서 결정한다.

## 10. 화면 완료 기준과 후속 연결

| 확인 경로·상황 | 완료 조건 |
|---|---|
| M01 → M02 → M03 | 폼 나열이 아닌 문답·요약·공개 확인 후 계획을 저장하고 에이전트가 후보를 제안 |
| M01 값·공개 범위 변경 | 소개·추천·차량·결말에 같은 지원값 반영. 비공개 항목·원문 대화가 상대에게 공개되지 않음 |
| 공개 보류·연결 거절 | 상대 기능은 열리지 않지만 내 에이전트·본인 여행·본인 모드 차량 이어받기는 유지 |
| M04 → P01 | 전달 준비와 차량 확인 구분. 불러오기 실패·오래된 연결에서 샘플 성공으로 대체하지 않음 |
| P02 S06 ↔ S07 | 캐릭터 답변은 B 이벤트 없이, 사용자 메시지는 확인·전송·B 답변으로 구분 |
| P02 콘텐츠 이동 | 순서 변경·건너뛰기·휴식 가능. 미전송 문장 자동 전송·새 답장 자동 재생 없음 |
| 일반 통화·MC | 각 동의·거절·취소·종료가 분리됨. MC 미구현·거절 시 일반 통화·만남 흐름 유지 |
| P03 만남·내비 | 양쪽 동일 제안 동의와 운전자 승인이 따로 필요. 요청·성공·실패·미확인·모의 표시 구분 |
| 내비 요청 중·후 취소 | 만남 취소 유지, 늦은 성공은 경유지 정리로 연결. 제거 미확인 상태에서 복귀 완료 표시 없음 |
| P03 → P04 | 만남 종료 후에만 최종 선택. 조기 종료에서 만남 완료·최종 선택·후기 생성 없음 |
| P04 두 결말 | 양쪽 함께일 때만 함께 결말. 한쪽 각자는 내 친구 대화·다음 활동. 상대 이유·평가나 A 의사 단정 없음 |
| 제한·재진입·중복 | 실제 제한 우선, 처리 중 중복 실행 방지, 화면 복귀·늦은 응답으로 동의·경로 요청 우회 없음 |
| O01 재시연·초기화 | 결말 재시연과 전체 초기화 범위 구분. 이전 회차 응답·외부 미정리 경로가 새 실제 시연에 섞이지 않음 |
| 무음·좁은 창·확대 | 자막·버튼·오류·확인 패널이 가려지지 않고 키보드·초점·라벨로도 진행 가능 |
| 추가 기능 제외 | P05·MC·이유 남기기가 없어도 S01~S12·DM01~DM09·DM11 완주 |

실제 레이아웃·음성·주행·SDK 동작은 구현 후 검수한다. 문서 작성과 구조 확인만으로 위 화면이 구현·검증됐다고 기록하지 않는다.

서비스 효과·이해도는 05번 V01~V05에서 별도로 확인한다. 화면 완주·자막 일치·O01 모의 성공은 방문 캐릭터의 실제 효과나 동행감의 통과 근거가 아니다. 늦은 응답·새 시각 합의는 검증용 상황으로 두고 현재 화면에 자동 재계산·여행 전 장소 합의 기능을 추가하지 않는다.

04번 개발 명세서는 이 화면 ID·상태·활성 조건을 코드·공통 데이터·요청 수명·복원·주행 제한·SDK에 연결한다. 05번 업무·검수표는 화면·분기별 담당과 확인 결과를 기록한다. 범위를 바꾸면 01번 기능 범위와 02번 대본·시연 시간에도 함께 반영한다.
