# wayMate 시연 시나리오 및 대본

작성일 2026년 11월 10일 · 수정일 2026년 11월 11일 · 버전 0.6 · 팀 공유용 수정안

**내 에이전트와 대화하며 나와 여행을 준비하고, 상대의 캐릭터를 통해 서로 익숙해진 뒤 잠깐 만난다. 이후에는 사람과 함께 여행하거나 내 캐릭터와 본인의 여정을 이어간다.**

기준은 [01. 목업 기획 및 범위 정의서 v0.6](01_목업_기획_범위_정의서.md)다. 기존 02번 초안의 장면 ID `S01`~`S13`을 유지하고 대화형 온보딩, 에이전트의 제안, 선택형 차량 콘텐츠, 경로 기반 만남, 두 결말을 반영한다. 장면은 이야기의 단위이며 화면 수와 같지 않다. 후속 화면·개발·검수 문서에서도 장면 ID와 기능 ID `DM01`~`DM11`을 사용한다.

## 1. 시연 목표와 운영 기준

**전달할 메시지: 나를 알아가는 캐릭터와 여행하고, 마음이 맞는 순간에는 다른 여행자와 함께한다.** 온보딩의 한마디가 캐릭터의 소개, 추천, 실제 만남, 내 캐릭터와의 여행까지 이어지는 모습을 보여준다.

| 구간 | 구성과 목표 시간 |
|---|---|
| 대표 시연 | 온보딩부터 함께 여행하는 결말까지 장면 합계 약 7분 40초. 기기 전환·발표 설명을 포함해 약 8분 |
| 다른 결말 | 최종 선택 직전으로 돌아가 내 캐릭터와 이어가는 결말을 약 60초 추가 |
| 추가 콘텐츠 | MC 통화 약 30초, 후기·캐릭터 변화 약 20초. 기본 시연 시간에는 포함하지 않음 |
| 별도 검수 | 공개 범위, 다른 답변, 콘텐츠 건너뛰기·종료, 연결·통화·만남 거절, B의 각자 여행 선택, 전달·내비 실패·취소, 주행 제한, 재시연 |

발표자는 A를 조작한다. B의 수락·메시지·통화 동의·최종 선택은 시연자가 현재 상태에 맞는 이벤트로 재현한다. B의 실제 계정이나 두 번째 차량 앱을 필수로 만들지 않는다. 시연자 제어는 사용자 버튼과 구분한다. 위 시간은 발표용 목표이며 자동 응답·대기 만료시간이 아니다.

온보딩의 사용자 답변은 자유 입력하고 후속 질문·소개 예시는 준비된 대사로 재현한다. 입력 원문과 사용자가 확인한 구조화 소개값을 구분하며 추천은 시연 데이터를 사용한다. 자율 추론이나 실제 B의 실시간 응답을 구현했다고 설명하지 않는다. ‘대본 기반 시연’, ‘시연 음성’, ‘이동 경험 개념 시연’, ‘내비 모의 화면’ 표시는 발표용 상태 영역에 두고 사용자의 대사와 분리한다.

내비는 사전 검증 결과에 따라 실제 연동 또는 모의 모드로 시작한다. 실제 모드는 결과 확인 후에만 성공을 표시하고, 모의 모드는 해당 연동을 완료로 기록하지 않는다. 사용자 동의와 운전자 승인 순서는 어느 모드에서도 동일하다.

## 2. 등장인물·표현·여행 데이터

### 2.1. 인물과 에이전트

| 항목 | A 주인공 | B 상대 |
|---|---|---|
| 별명 | 기본값 파도. 변경 가능 | 솔바람. 고정 |
| 캐릭터 | 준비된 외형 중 선택 | 고정 프리셋 |
| 관심사 | 바다 산책·카페 | 바다 산책·카페 |
| 활동 선호 | 사진은 가끔, 느긋하게 쉬기 | 산책 우선, 사진은 가끔 |
| 여행·대화 스타일 | 느긋하게, 조용한 대화, 가끔 가벼운 농담 | 느긋하게, 조용한 대화, 부드러운 존댓말 |
| 확인한 소개 표현 | ‘바다 보며 멍때리기’, ‘커피 한 잔’, 가벼운 웃음 표현 | ‘천천히 가도 괜찮죠’, ‘바다부터 보고 커피’ |
| 만남 가능 시간 | 13:00~15:00 | 14:00~15:30 |
| 조작·응답 | 발표자의 입력·선택 | 고정 프로필과 시연자 이벤트 |

두 사람은 가상의 성인 여행자이며 각자의 차량을 이용한다. 동행은 같은 장소에서 활동하고 필요하면 각자 운전해 다음 장소로 가는 방식이다.

**B의 사전 경험:** 기본 이야기에서 B는 연결을 수락하기 전 A의 현재 승인된 소개를 확인했다. 여행 당일에는 정차 중 자신의 차에 방문한 A 캐릭터의 소개를 들었다고 설정한다. 따라서 만남에서 A의 공개 취향을 “들었다”고 말할 수 있다. 이 과정은 대본의 배경이며 실제 B 기기 접속·열람 확인이나 두 번째 앱 구현을 뜻하지 않는다. B 차의 소개를 화면으로 보여주는 것은 선택 연출이지만, 기본 대본의 이 배경은 유지한다.

B의 사전 접점 자체를 생략하는 변형은 storyContext.peerIntroSeen=false로 구분하고, 만남에서 MEETING_HELLO_GENERAL을 사용한다. 취향 공개를 제외한 경우에도 B가 그 취향을 미리 알았다고 말하지 않는다.

발화자 표시는 다음 기준으로 통일한다.

| 표시 | 뜻과 대사 원칙 |
|---|---|
| 나 / 솔바람 | 실제 사용자의 입력·발언을 나타낸다. B의 발언과 통화는 이번 시연에서 대본으로 재현한다. |
| 내 에이전트 | A와 대화하는 친구다. 온보딩에서 확인한 A의 취향을 기억하고 여행을 돕는다. |
| 솔바람의 에이전트 | A의 차를 방문한 B의 캐릭터다. 승인된 B의 정보와 표현 스타일로 소개하되 자신을 B 본인이라고 소개하지 않는다. |
| 솔바람의 메시지 · 에이전트가 읽어줌 | B가 보낸 문장을 그대로 전달하는 장면이다. 캐릭터의 프로필 기반 답변과 구분한다. |
| MC 에이전트 | 두 사람의 동의를 받고 통화에 참여하는 진행자다. MC 추가 장면에서는 내 에이전트 한 명을 MC로 사용한다. |

원문 온보딩 대화, 실명·전화번호·생년월일·차량번호·정밀 출발지·현재 좌표·숙소 주소·전체 개인 일정은 상대에게 전달하지 않는다. 공개를 승인한 관심사·소개 표현·활동 권역·공통 시간과 합의한 만남 정보만 사용한다. 상대에게는 일정 충족 여부를 요약해 보여주며, 상세 다음 일정과 복귀 시각은 본인 화면에서만 확인한다.

아래 `{내별명}`은 저장한 별명으로 치환하는 자막·UI 표기다. 중괄호를 화면에 출력하지 않는다. 준비된 음성은 A의 별명을 직접 부르지 않는 문장으로 녹음해 별명 변경과 충돌하지 않게 한다. 온보딩의 A 답변은 채팅 텍스트이며, 통화·만남의 A 음성은 시연용 샘플이다.

### 2.2. 일정과 이야기 속 시각

| 항목 | A | B |
|---|---|---|
| 여행일·권역 | 2026년 11월 14일 · 강릉 해변권 | 동일 |
| 공통 가능 시간 | 14:00~15:00, 60분. 실제 만남 길이가 아니라 약속을 잡을 수 있는 범위 | 동일 |
| 만남 장소 | 바다쉼표 카페 · 가상 공개 장소 | 동일 |
| 첫 만남 | 14:15~14:35, 20분 | 동일 |
| 만남 장소 도착 예정 | 14:02 | 14:10 |
| 만남으로 인한 추가 주행 | 7분 | 5분 |
| 함께 이어갈 활동 | 14:35~14:55 · 카페 옆 해변 산책 | 동일 |
| 기존 다음 일정 도착 | 15:20 기존 개인 방문지 · 강릉권 가상 일정 | 15:15 기존 개인 방문지 · 강릉권 가상 일정 |
| 본인 복귀 장소 | 본인 숙소 · 강릉권 가상 장소, 상대 비공개 | B 본인의 별도 숙소 · 상대 비공개 |
| 숙소 도착 예상·마감 | 예상 15:45 · 늦어도 16:00 | 예상 15:40 · 늦어도 16:00 |

수치는 01번의 가상 데이터를 사용하며 실제 장소의 영업·주차 확인이나 실시간 교통 계산 결과가 아니다. 일정은 만남·대기·추가 활동·다음 방문·복귀를 모두 포함하는 것으로 설정한다. 함께 걷는 활동은 14:55에 끝내 공통 시간 종료 전 여유를 둔다. 각자 가는 결말에서도 A는 원래 계획한 해변에서 쉬고 15:20 다음 방문으로 이어간다.

**A의 13:00~15:00은 두 시간 동안 B를 만난다는 뜻이 아니다.** B의 가능 시간과 겹치는 14:00~15:00 안에서, 첫 만남은 14:15~14:35의 20분만 합의한다. 도착 뒤 A는 13분, B는 5분을 기다렸다가 14:15에 만난다. 이후 양쪽이 원하면 14:35~14:55에 함께 걷고, 아니면 내 캐릭터와 본인 활동을 이어간다. 어느 결말이든 15:20의 기존 개인 일정과 이후 숙소 복귀 계획을 유지한다.

A의 시간 순서는 **만날 수 있는 범위 확인 → 카페에서 20분 만남 → 함께 또는 각자 20분 활동 → 15:20 기존 일정 → 15:45 숙소 도착 예상 → 16:00 숙소 도착 마감**이다. ‘다음 방문’은 연결 전부터 있던 일정이고 ‘복귀’는 그 일정을 마친 뒤 숙소로 돌아가는 뜻이다. 서로 다른 장소·시각이며, 숙소 주소와 개인 방문지의 상세는 본인에게만 보인다.

모바일 준비는 여행 전, 차량 이어받기는 여행 당일 출발 전의 주차 상태다. S06~S08은 여행 중 이동 시간을 활용하는 서비스 장면으로 구성한다. S09의 만남 제안 확인·내비 승인 기준 시각은 **13:50의 짧은 정차 구간**으로 두며, 이후 A·B의 도착 예정은 각각 14:02·14:10이다. 실제 발표 시간과 이야기 속 시간은 별개이며, 발표자가 오래 머물러도 수치를 실시간 재계산하지 않는다.

목업에서는 S06~S08의 선택·전송·통화 시작을 주차 상태에서 조작하고 준비된 음성으로 이동 경험을 설명한다. 실제 제한 상태에서의 앱 지원과 개념 시연을 구분하는 방법은 7절에 둔다.

대표 이야기는 B도 제안을 확인·응답할 수 있는 정차 시점이라는 가정이다. 늦게 확인하는 실제 상황에서 같은 도착·만남 시각이 그대로 성립한다고 보장하지 않는다. 그 경우의 제안 유지·취소·새 시각 합의는 05번 V03에서 별도 검증하며, 기본 목업에 자동 마감·시간 재계산 기능을 추가한 것은 아니다.

후보는 B ‘솔바람’, C ‘노을’, D ‘산들’ 3명이다. C는 카페·공통 시간 40분, D는 산책·공통 시간 30분의 요약 카드로 제공한다. B만 상세와 연결 요청을 진행한다. C·D는 ‘요약 보기’로 표시하고 연결 기능이 있는 것처럼 보이지 않게 한다.

### 2.3. 공개 범위·표현·건너뛰기에 따른 대사

이하 본문은 관심사·표현을 공개한 기본 시연의 대본이다. 공개를 줄이거나 콘텐츠를 건너뛰었을 때 같은 문장을 무조건 재생하지 않는다. 현재 공개 필드와 실제로 표시한 대사를 확인해 아래 변형을 사용한다. 직접 확인해 보낸 사용자 메시지·통화 발언은 해당 문장의 공유이며 공개 프로필을 자동 변경하지 않는다.

| 대사 ID | 조건·사용 위치 | 실제 대사·동작 |
|---|---|---|
| OWN_PRIVATE_START | S01 전체 공개 보류 | 내 에이전트: “소개는 아직 나만 볼게. 우선 네 여행부터 준비하자.” |
| OWN_PRIVATE_PLAN | S02 소개 또는 여행 요약 공개 보류 | 내 에이전트: “이 계획은 네 여행용으로 저장했어. 다른 사람에게는 공유하지 않고 나랑 이어갈 수 있어.” 후보 대신 본인 여행으로 이동 |
| OWN_SUMMARY_CALM | S01 차분한 표현 선택 | 내 에이전트: “바다와 카페를 좋아하고, 한 곳에서 느긋하게 쉬는 편이구나. 대화는 차분하고 편안하게. 이렇게 이해하면 될까?” |
| INTRO_CALM | S01 방문 소개, 해당 관심사·성향 공개 + 차분한 표현 | “별명은 {내별명}. 바다를 천천히 보고 카페에서 쉬는 여행을 좋아해. 조용히 함께 있는 시간을 편하게 느끼는 친구야.” |
| INTRO_NEUTRAL | 방문 소개에서 취향·표현 공개를 제외 | “{내별명}의 캐릭터예요. 여행 이야기는 직접 나눠봐도 좋아요.” 최소 소개만 사용하며 비공개 부분을 빈칸에 다시 넣지 않음 |

S01 네 번째 질문의 차분한 예시 답변은 “차분하고 담백하게 말해줘”다. 입력만으로 프리셋을 추정하지 않으며 별도 소개값 확인에서 차분한 표현을 선택한 경우에만 요약·방문 소개·내 친구 결말의 대사와 녹음 모두에 반영한다. 표현 공개를 제외하면 방문 캐릭터는 INTRO_NEUTRAL을 쓰지만, 본인의 내 친구는 본인이 선택한 표현을 유지한다. 음성의 변경 가능한 별명은 생략하고 자막에는 저장값을 사용한다.

콘텐츠 생략은 과거에 대화했다는 근거가 아니다. 기본 S08·S10의 ‘캐릭터에게 들었다’, ‘말투가 익숙하다’는 표현은 관련 S06 대사가 실제 표시된 경우에만 사용한다. 이력 확인이 안 되면 일반 인사 대본을 고른다. 기본 시연 시간표는 기존 대표 경로 기준이며 변형의 실제 시간은 리허설에서 확인한다.

기본 Q1 답변 cueId는 S06_Q1_ANSWER, 기본 S08 A 인사는 S08_PLAIN_A_HELLO, 기본 S10 만남 묶음은 S10_MEETING_FAMILIAR로 등록한다. 뒤의 두 기본 묶음은 S06_Q1_ANSWER 표시 이력과 필요한 공개 필드를 요구한다. Q2만 봤거나 Q1의 모름/대체 답변만 본 경우는 이를 충족하지 않는다. 해당 공개 근거나 부분 공개용 대본이 없으면 CALL_HELLO_GENERAL·MEETING_HELLO_GENERAL·INTRO_NEUTRAL을 사용한다. 표시 이력은 동의나 실제 이해·열람의 증명이 아니다.

S10_MEETING_FAMILIAR에는 B의 사전 경험인 storyContext.peerIntroSeen=true도 필요하다. A가 B 캐릭터의 답변을 봤다는 이력만으로 B도 A 소개를 들었다고 간주하지 않는다. 이 전제가 없거나 현재 A 공개 소개에 해당 취향이 없으면 B도 일반 인사로 바꾼다. S08 A 인사는 기존 Q1·공개 필드 조건으로 판단한다.

목록에는 ‘만남 제안 받기’와 ‘지금은 쉬기’를 별도로 둔다. 연결이 유지되고 양쪽 공통 시간이 유효한 대표 설정이면 S06·S07·S08을 모두 마치지 않아도 S09로 갈 수 있다. ‘지금은 쉬기’는 콘텐츠만 일시 중단하며 연결을 종료하거나 만남에 동의하지 않는다. ‘연결 마무리하기’를 선택한 경우에는 만남 대신 내 캐릭터와 본인 여정을 이어간다.

이 목록은 서로 알아가고 스몰토크를 돕는 경험의 **목업용 대표 구성**이다. 확장 아이디어로 ‘바다 산책 vs 카페에서 쉬기’ 같은 여행 취향 밸런스 게임을 소개할 수 있다. 예를 들어 에이전트가 “가볍게 골라볼까요? 바다를 걸으며 이야기하기, 카페에 앉아 이야기하기 중 어떤 쪽이 편해요?”라고 주제를 꺼내는 방식이다. 이 문장은 기획 설명용 예시이며 새 실행 버튼·게임 진행·B의 선택을 구현한 대본은 아니다. 제작 채택은 미정이고 대표 시연 시간에 추가하지 않는다.

## 4. 모바일 온보딩·여행 준비 대본

### S01. 내 에이전트와 처음 알아가기 · DM01

실제 가입 대신 ‘데모로 시작하기’로 진입한다. 에이전트가 한 번에 한 질문을 건네고, A는 빈 입력창에 자기 말투로 답을 직접 쓴 뒤 ‘이 답변 보내기’를 누른다. 예시 칩은 입력창에 수정 가능한 초안만 넣고 전송하지 않는다. 아래 대표 답변은 시연자가 입력할 대본이며 허용 답변 목록이 아니다. 별명은 직접 입력하고 캐릭터 외형은 채팅 안 카드에서 선택한다.

| 차례 | 내 에이전트 | A의 대표 답변 | 확인할 정보 |
|---|---|---|---|
| 1 | “안녕! 앞으로 네 여행에 같이 갈 친구야. 쉬는 날엔 뭘 할 때 제일 좋아?” | “바다 보면서 멍때리다가 카페 가는 게 좋아 ㅋㅋ” | 바다 산책·카페 관심사 |
| 2 | “여행할 때는 어떤 식으로 시간을 보내는 편이야?” | “한 곳에 오래 있는 편이야. 사진도 가끔 찍고.” | 요약에서 본인이 확인할 여행 속도 |
| 3 | “처음 만난 사람이랑은 어떤 대화가 편해?” | “말이 많지 않아도 편한 게 좋아. 조용히 같이 있어도 괜찮고.” | 조용한 대화 선호 |
| 4 | “널 소개할 땐 어떤 느낌으로 말해주면 좋겠어?” | “편하게 말하고, 가벼운 농담도 조금 해줘 ㅎㅎ” | 요약에서 본인이 별도 확인할 표현 |
| 5 | “좋아. 뭐라고 불러줄까? 네 캐릭터 모습도 골라줘.” | “파도라고 불러줘.” + 외형 선택 | 별명·캐릭터 |

질문 1~4는 모두 자유 입력이다. 질문 5는 별명 입력·외형 선택이다. 입력한 문장·띄어쓰기·이모지·ㅋㅋ/ㅎㅎ를 원문으로 보존하며 자동 성격 분석은 하지 않는다. 다음 질문은 차례에 따른 준비 대사다. 요약은 원문을 다시 보여주고 별도 소개값 확인 카드를 제공한다. 대표 시연의 소개 대사는 A가 바다·카페·여유로운 여행·조용한 대화·가벼운 농담을 직접 확인한 경우만 사용한다. 표현을 확인하지 않으면 중립 표현을 쓴다. 실제 억양·말의 속도·표정을 추출했다고 표시하지 않는다.

> **내 에이전트:** “소개는 이렇게 해보면 어떨까? 너와 맞는 내용만 확인해줘.”

‘내가 쓴 답변’과 ‘소개 예시·지원값 확인’ 카드를 구분한다. 대표 시연의 소개 예시는 바다·카페·여유로운 여행·조용한 대화·가벼운 농담이다. ‘이 소개값 확인 / 수정 / 이 소개값은 쓰지 않을래’를 제공하고 본인이 확인한 값만 소개에 반영한다. 확인하지 않은 항목은 비워두고 최소 소개/일정 중심 추천 또는 본인 여행으로 이어간다. 원문을 예시 답변으로 다시 쓰도록 강제하지 않는다.

**상대 차에서 보일 소개 미리보기**

> **내 캐릭터의 소개 예시:** “별명은 {내별명}. 바다 보면서 느긋하게 쉬는 걸 좋아해. 커피 한 잔도 빠질 수 없대 ㅎㅎ. 조용히 같이 있어도 편한 여행을 좋아하는 친구야.”

미리보기는 자막 기준이다. 음성에서는 별명을 생략하고 같은 내용을 읽는다. 공개할 항목을 확인하고 ‘이 소개로 시작하기’를 눌러야 공개 프로필 준비가 완료된다. ‘지금은 나만 보기’는 본인 요약만 확인하고 S02 본인 여행으로 이어간다. 원문 채팅과 비공개 일정은 제외한다. 관심사·표현을 제외하면 2.3절 변형을 사용한다. 대표 시연에서는 위 소개 항목을 공개한다.

> **내 에이전트:** “좋아. 네가 알려준 것부터 천천히 알아갈게. 이번엔 어떤 여행을 가고 싶어?”

### S02. 여행 희망을 계획으로 정리하기 · DM02

> **A:** “11월 14일에 강릉 가려고. 바다도 보고 카페에서 좀 쉬고 싶어.”
>
> **내 에이전트:** “좋아. 다른 여행자랑 잠깐 만날 수 있는 시간과, 꼭 지키고 싶은 기존 일정이 있어?”
>
> **A:** “오후 1시부터 3시 사이에 만날 수 있어. 3시 20분에 원래 가려던 곳이 있고, 4시까지는 숙소로 돌아가고 싶어.”
>
> **내 에이전트:** “그 시간 안에서 잠깐 만날 수 있는 사람을 알아볼게. 3시 20분 기존 일정은 유지하고, 숙소 도착은 3시 45분 예상, 늦어도 4시까지인 계획이야. 확인해줘.”

여행 카드에 2026년 11월 14일, 강릉 해변권, ‘만남 가능 시간 13:00~15:00’을 표시한다. 본인 전용 카드는 ‘기존 다음 일정 도착 15:20’, ‘내 숙소 도착 예상 15:45’, ‘내 숙소 도착 마감 16:00’으로 나눠 보여준다. 가능 시간 전체를 약속으로 표시하거나, 숙소 도착 마감을 다음 방문 시각과 합치지 않는다. 대표 프리셋 확인·저장이며 자유로운 날짜·지도 검색이나 일정 계산을 구현한 것으로 설명하지 않는다. 숙소 도착 예상은 이번 계획의 준비된 시연값이다.

이 단계에서는 상대·만남 장소·약속 시각이 아직 정해지지 않았다. 14:15~14:35는 뒤의 S09에서 양쪽이 수락한 후에만 확정된 첫 만남으로 표시한다.

‘상대에게 보일 여행 요약’에는 여행일·강릉 해변권·가능 시간 13:00~15:00만 보여주고 공유 여부를 확인한다. 다음 방문·복귀 계획은 본인용이다. ‘이 계획 저장하기’는 본인 계획을 저장하며, 소개와 여행 요약 공개가 모두 승인된 경우에만 추천 준비로 간다. 하나라도 보류하면 OWN_PRIVATE_PLAN과 본인 여행·차량 이어받기를 제공한다. 정확한 날짜·시각은 확인 카드로 보여주어 자연어 문장만으로 확정되지 않게 한다.

### S03. 내 에이전트가 먼저 후보를 제안하기 · DM03

계획 저장 뒤 추천 알림과 후보 카드가 나타난다. 사용자가 다시 ‘매칭 찾기’를 눌러야만 후보가 생기는 흐름으로 만들지 않는다. 추천을 준비하는 상태는 시연 데이터 조회이며 실제 탐색·점수 계산 완료로 설명하지 않는다.

> **내 에이전트:** “네 여행이랑 잘 맞는 사람을 찾아봤어. 솔바람도 바다 산책이랑 조용한 카페를 좋아해. 같은 날 강릉에 있고, 함께할 수 있는 시간이 한 시간 겹쳐.”
>
> **A:** “일정이 너무 돌아가진 않을까?”
>
> **내 에이전트:** “준비된 여행 계획 기준으로, 만날 수 있는 장소 후보에 들르면 추가 이동은 7분 정도야. 장소는 아직 정한 게 아니고, 만나고 싶어지면 두 사람 일정에 맞춰 제안할게.”

B 카드에는 공통 관심사, 강릉 해변권, 공통 시간 14:00~15:00·60분, 시연 계획 기준 예상 추가 이동 7분을 표시한다. 이 값은 사전 비교용 예상이며 만남 장소 확정·실시간 재계산 결과와 구분한다. S09에서 같은 가상 경로의 상세 수치를 확인한다.

C·D의 요약 카드는 비교용으로 보여주고 B 상세에서만 ‘대화 연결 요청’을 제공한다. B 상세의 관심사·표현은 승인된 공개 프로필에 한정한다.

### S04. 알아갈 의사를 서로 확인하기 · DM04

> **내 에이전트:** “먼저 캐릭터랑 편하게 이야기해볼래? 연결돼도 통화나 만남은 따로 선택하면 돼.”

A가 ‘대화 연결 요청’을 누르면 ‘솔바람님의 응답을 기다리고 있어요’를 표시한다. 시연자가 **B 연결 수락**을 실행한 뒤 공통 날짜·시간을 보여준다.

> **안내:** “솔바람님도 대화 연결을 수락했어요. 11월 14일, 공통 가능 시간은 14:00~15:00예요.”

A가 ‘이 시간대로 연결하기’를 눌러야 **대화 연결 완료**로 바뀐다. 이 단계에서 통화·만남·최종 동행을 수락한 것으로 처리하지 않는다.

> **내 에이전트:** “이야기할 준비가 됐어. 여행 당일 차에서 네 캐릭터와 여행 계획을 이어갈 수 있어.”

웹은 A의 승인한 프로필·표현 프리셋·캐릭터·여행 계획·B 연결 상태를 저장한다. B 수락과 A 시간 확인 전에는 연결된 상대와의 차량 콘텐츠를 시작하지 않는다. 요청 취소·거절 시에는 본인 여행과 내 에이전트가 유지되는 별도 종료 안내를 사용한다.

이번 회차의 연결을 거절·취소·종료한 뒤 새 연결을 요청하려면 전체 초기화로 다시 시작한다. 요청 이후의 프로필·계획 재설정도 같은 기준이다. 본인 여행의 조회·대화는 계속 가능하며, 최종 선택 재시연은 새 매칭 요청이 아니다.

## 5. 차량 이어받기와 선택형 대화 대본

### S05. 차에서도 같은 친구와 여행 이어가기 · DM05

여행 당일 출발 전 주차 상태다. 웹에서 ‘차량에서 이어가기’로 전달 준비를 마치고 차량 앱의 ‘내 여행 불러오기’를 누른다. 불러오기 성공 전에는 웹에 차량 연결 성공을 표시하지 않는다.

저장한 별명·외형·관심사·표현·강릉 일정·B 연결 정보가 일치하는지 확인한다.

> **내 에이전트:** “왔네! 바다 보고 커피 한 잔 하는 여행, 준비한 그대로 이어갈게. 솔바람의 캐릭터도 인사하러 왔어.”
>
> **솔바람의 에이전트:** “반가워요. 저는 솔바람의 캐릭터예요. 만나기 전에 솔바람이 어떤 여행을 좋아하는지 편하게 물어봐 주세요.”

‘솔바람의 에이전트 · 공개 프로필 기반’ 표시와 콘텐츠 목록을 보여준다. 내 에이전트는 계속 이용 가능하다. 캐릭터가 상대 차를 방문한다고 해서 내 친구가 사라지거나 전체 대화 기록이 상대에게 넘어가는 것은 아니다.

발표용으로 B의 차에 방문한 A 캐릭터의 소개를 짧게 보여줄 수 있다. S01에서 승인한 소개를 그대로 사용하며, B 기기의 실제 접속·동시 통신 시연을 필수로 만들지 않는다.

### S06. 상대 캐릭터와 먼저 익숙해지기 · DM06

A가 ‘상대 캐릭터와 알아가기’를 선택한다. 이 장면은 **B 본인에게 메시지를 보내지 않고**, 공개 프로필을 바탕으로 B의 캐릭터와 대화한다. B 답변 이벤트를 기다리지 않는다.

| 선택 | A가 캐릭터에게 하는 질문 | 솔바람의 에이전트 답변 |
|---|---|---|
| Q1 대표 질문 | “솔바람은 여행할 때 뭘 제일 좋아해?” | “천천히 가도 괜찮죠. 솔바람은 바다를 먼저 보고, 조용한 카페에서 커피 한 잔 하는 걸 좋아해요. 사진도 좋지만 느긋하게 걷는 쪽이래요.” |
| Q2 다른 질문 | “처음 만나면 무슨 얘기를 하면 좋을까?” | “둘 다 바다 산책이랑 카페를 좋아하니까, 오늘 본 바다 이야기로 시작해보면 어때요? 솔바람도 조용히 같이 있는 시간을 편하게 느낀대요.” |

‘천천히 가도 괜찮죠’는 B가 공개 프로필에서 확인한 표현 프리셋이다. 상대의 분위기를 느끼게 하되, 실제 B가 지금 이 질문에 답했거나 현재 감정·의사를 전달한 것으로 표시하지 않는다. 공개 정보에 없는 질문에는 “그건 제가 아는 소개에는 없어요. 직접 물어볼까요?”라고 답하고, 사용자가 원하면 S07의 보낼 말 확인으로 간다. 자동 전송하지 않는다.

> **A:** “그럼 바다 먼저 보고 커피 마시는 걸 좋아하는구나.”
>
> **솔바람의 에이전트:** “맞아요. 나중에 만나면 편하게 꺼낼 수 있는 이야기겠죠?”

‘콘텐츠 목록으로’를 누르면 다른 방식을 고를 수 있다. 내 에이전트를 선택하면 짧은 친구 대화를 제공한다.

> **내 에이전트:** “너도 바다 보며 느긋하게 쉬는 걸 좋아하잖아. 말할 주제가 생겼네. 더 알아가도 좋고, 잠깐 쉬어도 좋아.”

이동 시간의 대화를 재현하는 음성 장면은 7절의 제한 기준을 따른다. 화면을 읽거나 연속 선택해야만 주행 장면이 이어지게 만들지 않는다.

### S07. 에이전트로 내 말 전하기 · DM06

A가 ‘에이전트로 말 전하기’를 선택한다. 캐릭터와 나눈 사적인 대화를 그대로 보내지 않고, 전달할 문장을 별도 카드로 확인한다.

> **내 에이전트:** “이건 솔바람에게 직접 전할 말이야. 보낼 문장을 먼저 확인해줘.”

| 선택 | A가 확인해 보낼 문장 | B 메시지 이벤트의 답변 |
|---|---|---|
| M1 대표 메시지 | “카페에서 쉬었다가 잠깐 바다를 걷는 건 어떠세요?” | “좋아요. 천천히 가도 괜찮죠? 저도 바다 보면서 쉬고 싶었어요.” |
| M2 다른 메시지 | “저는 조용한 카페가 편한데, 어떤 분위기를 좋아하세요?” | “저도 조용한 곳이 좋아요. 바다가 보이면 더 좋고요.” |

A가 ‘이 말 보내기’를 눌러야 전송한다. 이후 ‘솔바람님의 답장을 기다리고 있어요’를 표시하고, 시연자가 **B 메시지 답변**을 실행하면 선택한 메시지에 맞는 답장만 재생한다.

> **내 에이전트:** “솔바람에게 답장이 왔어. 읽어줄게.”
>
> **솔바람의 메시지 · 에이전트가 읽어줌:** “좋아요. 천천히 가도 괜찮죠? 저도 바다 보면서 쉬고 싶었어요.”

이어지는 B의 질문도 같은 대본 이벤트의 사용자 메시지로 구분한다.

> **솔바람의 메시지:** “사진 찍는 것과 천천히 걷는 것 중에는 뭘 더 좋아하세요?”

A는 아래 답변 중 하나를 선택하고 ‘답변 보내기’로 확인한다.

- R1: “저는 천천히 걷는 쪽이 좋아요. 사진은 가끔 한 장씩 찍고요.”
- R2: “사진도 좋아하지만, 오늘은 느긋하게 쉬고 싶어요. 다음 일정도 지키면서요.”

전달 완료 뒤 내 에이전트가 “서로 어떤 여행을 좋아하는지 조금 알게 됐네. 이 답장만으로 만남이 정해진 건 아니야. 다음은 네가 고르면 돼”라고 말한다. 콘텐츠 목록으로 돌아간다. B의 메시지를 캐릭터가 임의로 만든 답변이나 만남 수락으로 취급하지 않는다.

### S08. 직접 통화하고 싶을 때 선택하기 · DM07

‘둘이 직접 통화하기’를 선택한다. 통화를 하지 않아도 만남 제안을 받을 수 있다.

> **내 에이전트:** “직접 목소리로 인사해볼래? 둘 다 원할 때만 연결할게.”

A의 ‘통화 제안하기’와 **B 통화 동의** 이벤트가 모두 확인된 뒤에만 ‘시연 통화’와 샘플 음성을 재생한다.

> **A 샘플 음성:** “안녕하세요. 캐릭터한테 바다 먼저 보고 커피 마시는 걸 좋아한다고 들었어요.”
>
> **B 샘플 음성:** “반가워요. 네, 천천히 가도 괜찮죠. 오늘은 저도 느긋하게 쉬고 싶어요.”
>
> **A 샘플 음성:** “저도요. 그러면 편하게 이야기할 수 있겠네요.”

일반 통화에는 에이전트가 자동으로 끼어들지 않는다. ‘통화 종료’는 콘텐츠 목록으로 돌아가며 만남을 자동 확정하지 않는다. A의 취소·건너뛰기와 B의 통화 거절도 통화만 생략한다. 실제 마이크 입력·전화번호 교환·사용자 간 통신은 이번 장면에 포함하지 않는다.

### S08-MC. 에이전트와 함께 어색함 풀기 · DM07 · 추가

추가 장면을 구현한 경우에만 활성화한다. 일반 통화 동의에 더해 A와 B가 MC 참여를 각각 확인한 뒤, 내 에이전트 한 명이 진행자로 참여한다. MC를 거절하면 일반 통화나 다른 콘텐츠를 계속 이용할 수 있다. 대화 원문을 MC가 임의로 공개하는 연출은 하지 않는다.

> **MC 에이전트:** “두 분 다 바다랑 조용한 카페를 좋아하신대요. 오늘 바다에 가면 꼭 하고 싶은 게 하나씩 있을까요?”
>
> **A 샘플 음성:** “저는 그냥 파도 소리 들으면서 좀 멍때리고 싶어요.”
>
> **B 샘플 음성:** “저도요. 사진 한 장만 찍고 천천히 걷고 싶네요.”
>
> **MC 에이전트:** “벌써 여행 속도가 비슷하네요. 이제 편하게 이야기 나누세요. 필요하면 다시 불러주세요.”

MC는 짧게 주제를 던진 뒤 물러난다. 답변을 재촉하거나 다음 활동을 대신 약속하지 않는다. ‘MC 빼고 계속하기’는 일반 통화로, ‘통화 종료’는 콘텐츠 목록으로 돌아간다. MC 장면을 제거해도 기본 시연과 만남 흐름이 유지되어야 한다.

## 6. 에이전트의 만남 제안·실제 만남·두 결말

### S09. 두 경로에 맞는 곳에서 잠깐 만나기 · DM08

대표 이야기에서는 대화를 나눈 뒤 13:50 정차 구간에 들어온다. 사용자가 콘텐츠 목록의 ‘만남 제안 받기’를 누르면 내 에이전트가 준비된 가상 장소를 제안한다. 현재 위치를 실시간 수집·분석했다고 설명하지 않는다.

> **내 에이전트:** “두 사람 경로에서 조금만 들르면 되는 바닷가 카페가 있어. 조용한 분위기를 둘 다 좋아하니까 잘 맞을 것 같아. 바다쉼표 카페에서 20분 정도 만나볼래?”
>
> **A:** “내 다음 일정은 괜찮아?”
>
> **내 에이전트:** “시연 계획 기준으로 너는 추가 이동 7분, 복귀 예상은 3시 45분이야. 솔바람도 본인 일정을 지킬 수 있는 설정이야. 두 사람 모두 같은 장소와 시간에 동의해야 확정할게.”

장소 카드에는 다음 내용을 보여준다.

- 바다쉼표 카페 · 가상 공개 장소 · 바다 전망과 조용한 분위기라는 추천 이유
- 11월 14일 14:15~14:35 · 20분
- 만남 장소 도착 예정 A 14:02·B 14:10 · 차이 8분
- 내 추가 주행 7분 · 양쪽 모두 기존 일정 유지 가능이라는 요약
- 내 도착 후 예상 대기 13분 · 첫 만남 20분 · 이후 산책 20분은 만남 후 별도 선택
- 본인 전용 일정 카드: 기존 다음 일정 도착 15:20 · 내 숙소 도착 예상 15:45 · 내 숙소 도착 마감 16:00

B 쪽 시연 데이터에는 추가 주행 5분·다음 방문 15:15·복귀 예정 15:40·마감 16:00을 둔다. A 화면에 B의 전체 일정이나 복귀점 정보를 펼쳐 보여주지 않는다. 주차·이용시간은 가상 장소 설정이며 실제 검수 완료 배지로 표현하지 않는다.

A가 ‘이 장소·시간 제안하기’를 누르면 B 대기 상태다. 시연자가 **B 만남 수락**을 실행한 뒤 동일 장소·시각·체류시간에 대한 양쪽 동의를 확인해 **만남 확정**으로 표시한다.

> **내 에이전트:** “두 사람 모두 같은 제안에 동의했어. 차에서 내비 반영을 승인하면 이동할 수 있어.”

장소 제안만으로 경유지를 추가하지 않는다. 거절·취소 시에는 약속과 상대 연결을 마무리하고 내 캐릭터와 본인 여행을 이어간다. 이는 실제로 만난 뒤의 ‘만남 종료’가 아니다. 이번 대표 시나리오에는 장소·시간 자유 편집을 넣지 않는다.

### S10. 승인한 장소로 이동하고 실제로 만나기 · DM08·DM11

**1. 운전자 승인과 내비 결과**

주차 상태에서 A가 ‘만남 카페를 경유지로 추가’를 누르면 처리 중으로 표시한다. 기존 다음 방문지를 목적지로 유지하고 승인한 만남 카페를 중간 경유지로 넣는다. 즉 ‘현재 위치 → 기존 다음 방문지’를 ‘현재 위치 → 만남 카페 → 기존 다음 방문지’로 바꾸며, 숙소를 새 목적지로 설정하는 동작이 아니다. 요청 전송과 실제 반영을 구분해 확인된 응답에 따라 성공·실패를 표시한다.

이 추가 요청을 보내기 전·처리 중·추가 확인 후에 약속을 취소할 수 있다. 약속 취소만으로 이미 보낸 내비 요청이 중단되거나 추가된 카페가 자동 제거됐다고 표시하지 않는다. 제거가 필요하면 “만남 카페를 빼고 기존 목적지로 계속 안내할까요?”라고 따로 확인한다. 상세 분기는 01번 5.3절, 화면·SDK 처리는 03·04번을 따른다.

실제 추가 성공, 모의 추가 성공, 또는 실제 실패가 확인된 뒤 별도로 승인한 모의 진행에서만 이동 장면으로 간다. 모의 모드 선택만으로 성공시키지 않는다. 모의 진행에는 ‘내비 모의 화면’을 유지하고, 실패 후 모의 전환을 실제 성공으로 바꾸어 기록하지 않는다. SDK 시험 좌표의 실제 경로와 위 가상 이동 수치를 같은 계산 결과로 설명하지 않는다.

모의 모드에서는 운전자 승인으로 생긴 추가 요청에 O01 ‘모의 추가 성공’을 지정한 뒤 이동한다. ‘모의 실패’·‘모의 미확인’도 같은 요청에 지정할 수 있고, 실패는 새 승인 후 재시도, 미확인은 결과 확인으로 분기한다. 제거 요청이 생기면 그 요청에도 별도 모의 결과를 지정한다. 실제 실패 후 모의 진행과 실제 응답 변경은 별개의 동작이며 상세 계약은 04번 NAV_MOCK_RESULT를 따른다.

**2. 도착·첫 만남 재연**

시연자가 **만남 시작으로 이동**을 실행하면 A·B 도착과 대기를 건너뛰어 14:15 카페 장면을 보여준다. 카페 장면은 이미지·자막·샘플 음성으로 구성한 재연이며, GPS 도착 감지나 실제 사용자의 만남 기록이 아니다.

> **A:** “솔바람님 맞으시죠? 반가워요.”
>
> **B:** “네, 반가워요. 바다부터 보고 커피 마시는 코스 좋아하신다고 들었어요.”
>
> **A:** “맞아요. 캐릭터랑 이야기하면서 취향이 비슷하다고 느꼈어요.”
>
> **B:** “천천히 가도 괜찮죠. 오늘은 저도 그렇게 쉬려고요.”
>
> **A:** “그 말, 캐릭터도 하던데요. 뭔가 벌써 익숙하네요.”
>
> **B:** “저랑 좀 닮았나요? 그럼 편하게 커피부터 마셔요.”

캐릭터가 사용한 B의 확인된 표현이 실제 B의 대사에서도 이어져, 첫 만남의 대화 소재와 익숙함을 보여준다. 기본 재연은 B의 사전 소개 경험과 A의 Q1 이력이 모두 있는 경우다. 어느 한쪽 접점을 생략한 변형은 2.3절 일반 인사를 사용한다. 이 장면은 서비스 가치를 설명하는 대본이며 실제 효과 검증 결과는 아니다. 사용자 검증에서는 ‘벌써 익숙하다’는 답변을 미리 제공하거나 유도하지 않는다.

시연자가 **만남 종료**를 실행하면 14:35, 각자 차량에 돌아와 주차한 S11로 간다. 시간 전환 자체로 최종 동행 동의를 만들지 않는다.

### S11. 만남 뒤 남은 여행은 각자가 선택하기 · DM09

만남 종료 이벤트가 첫 선택 화면을 준비하며, 이때 B의 선택 대기는 아직 없다. A가 함께를 선택했을 때만 B 응답을 연다. A가 처음부터 내 캐릭터와 이어가기를 고르면 B 응답을 만들지 않고 바로 해당 결말로 간다. 재시연도 같은 순서다.

일반 진행에서 선택 대기 중 상대 연결을 끝내면 B 대기를 닫고 내 친구와 이어가기만 선택할 수 있게 한다. A의 각자 선택을 자동 저장하거나 완료한 만남을 취소로 바꾸지 않는다.

> **내 에이전트:** “이제 남은 여행을 어떻게 이어갈까? 두 사람이 원하면 바다를 조금 더 걸어도 좋고, 네 여행을 나랑 이어가도 좋아.”

선택지는 ‘함께 여행 이어가기’와 ‘내 캐릭터와 여행 이어가기’다. 함께할 범위는 14:35~14:55 해변 산책이다. 본인의 다음 일정과 복귀 마감을 확인할 수 있으며, 동승이나 일정 전체 변경을 제안하지 않는다.

| A의 선택 | B의 선택 | 처리 |
|---|---|---|
| 함께 이어가기 | B 함께 이벤트 | 양쪽 모두 함께일 때만 S12-A |
| 함께 이어가기 | B 각자 이벤트 | S12-B. 상대의 개인적인 이유는 표시하지 않음 |
| 내 캐릭터와 이어가기 | 상대 선택과 무관 | 즉시 S12-B. 늦게 온 B의 함께 응답으로 뒤집지 않음 |

A가 함께를 선택하고 B가 응답하기 전에는 ‘솔바람님의 선택을 기다리고 있어요’를 표시한다. A는 대기 중에도 내 캐릭터와 이어가기로 변경할 수 있다. 앞선 연결·통화·만남 수락을 최종 동의로 재사용하지 않는다.

동시 선택은 서버에 확정 저장된 순서를 따른다. 아직 대기일 때 저장된 A의 각자 선택은 결과를 종료하지만, 이미 양쪽 함께 결과가 확정된 뒤 도착한 이전 화면의 변경 요청은 적용하지 않고 최신 결과를 보여준다. 확정 결과를 바꾸는 발표용 동작은 O01 최종 선택 재시연으로만 제공한다.

### S12-A. 사람과 함께 여행 이어가기 · DM09

> **안내:** “두 분 모두 함께를 선택했어요. 14:35~14:55, 바다 산책을 이어가세요.”
>
> **내 에이전트:** “둘 다 좋아하던 바다 산책이네. 천천히 다녀와. 다음 방문은 3시 20분이야.”
>
> **B:** “사진은 한 장만 찍고 천천히 걸을까요?”
>
> **A:** “좋아요. 오늘 여행 속도가 잘 맞네요.”

산책과 본인 다음 일정을 함께 보여준다. 선택만으로 새 경유지나 새로운 여행 계획을 자동 추가하지 않는다. 14:55 활동 종료 후 각자의 다음 일정으로 이어지는 요약으로 마무리한다.

### S12-B. 내 캐릭터와 여행 이어가기 · DM09

**만남을 마무리한 뒤의 공통 안내**

> **안내:** “이번 만남은 여기서 마무리하고, 각자의 여행을 이어가요.”

상대 연결을 종료한다. ‘실패’, 상대 평가, 동행하지 않은 이유를 요구하는 문구는 사용하지 않는다. A가 함께를 원했지만 B가 각자를 선택한 경우에도 A가 혼자 있고 싶어 했다고 단정하지 않는다.

> **내 에이전트:** “이제 네 여행은 어떻게 이어가고 싶어? 아까 바다 보면서 멍때리고 싶다고 했지.”
>
> **A:** “응. 지금은 바다 보면서 좀 쉬고 싶어.”
>
> **내 에이전트:** “좋아. 이번엔 나랑 천천히 가보자. 원래 가려던 해변에서 잠깐 쉬어도 다음 일정은 지킬 수 있는 계획이야.”
>
> **A:** “사진도 한 장 남기고 싶네.”
>
> **내 에이전트:** “좋지. 바다 한 장, 커피 한 잔. 아까 네가 좋아한다던 여행 그대로네 ㅎㅎ. 2시 55분쯤 다음 일정 준비를 해보자.”

온보딩의 ‘바다 보며 멍때리기·커피·편한 표현’을 다시 사용해 내 친구와의 관계가 이어짐을 보여준다. 해변에서 쉬는 다음 활동 카드와 기존 다음 일정 도착 15:20·내 숙소 도착 예상 15:45·내 숙소 도착 마감 16:00을 제공한다. 다음 일정과 이동시간은 준비된 시연값이다. 실제 경로 변경이 필요하면 별도 운전자 승인을 받아야 하며, 이 결말에서는 자동으로 내비를 바꾸지 않는다.

‘내 캐릭터와 계속하기’와 ‘오늘은 여기까지’를 제공한다. 대화를 끝내거나 이유를 입력하지 않아도 여행을 이어갈 수 있다. ‘이유 남기기’는 A가 각자 여행을 선택한 경우에만 추가로 제공할 수 있으며 필수 제작 항목이 아니다. 입력하더라도 상대에게 전달하거나 결과를 바꾸지 않는다.

이 결말은 일정 안내만 보여주는 종료 화면으로 만들지 않는다. 적어도 위의 친구 대화와 다음 활동까지 제공한다. 내 캐릭터와의 관계는 가입 때부터 이어지며, 동행이 성사되지 않았을 때만 등장하는 기능이 아니다.

### S13. 여행 후 기록과 캐릭터 변화 · DM10 · 추가

함께한 결말을 완성한 뒤 선택적으로 붙인다. 시연자가 **여행 종료 후**로 전환하면 기록 여부를 묻는다.

이 전환은 남은 개인 일정과 숙소 복귀를 마친 뒤의 후기 시점으로 이야기를 건너뛰는 연출이다. 14:35의 첫 만남 종료나 실제 도착 감지와 구분한다.

> **내 에이전트:** “오늘 여행에서 남기고 싶은 순간이 있어?”
>
> **A의 샘플 기록:** “조용히 바다를 보며 편하게 이야기했어요.”
>
> **내 에이전트:** “오늘을 기억하는 바다 산책 장식을 붙여볼까? 미리 보고 골라줘.”

‘내 캐릭터에 반영하기’를 눌러야 장식을 적용한다. ‘건너뛰기’는 그대로 종료한다. 상대 평가에 따른 자동 외형 변경이나 장기 기억 시스템을 구현한 것으로 설명하지 않는다.

## 7. 주행 장면·시연자 이벤트·재시연

### 7.1. 이동 경험과 실제 제한 상태 구분

서비스 목표는 이동 중 음성으로 서로 알아가는 경험이다. 실제 Pleos 주행 중 지원 범위는 [01번의 주행 제한 기준](01_목업_기획_범위_정의서.md#72-이동-중-경험과-주행-제한)에 따른 별도 검증 항목이다. 이 문서의 대본이 실제 주행 중 허용을 뜻하지 않는다.

목업의 질문 선택·메시지 전달 확인·콘텐츠 선택·통화 시작·MC 참여·만남 동의·내비 승인은 주차 상태에서 진행한다. S06~S08은 정차 상태의 대본 재생 또는 별도 발표용 음성 장면으로 이동 경험을 설명한다. 플랫폼이 앱을 가리거나 오디오·조작을 제한하면 그 동작을 따르고 우회하지 않는다.

실제 제한 검수에서는 사용자 입력과 다음 장면 진행을 멈추고, 준비된 B 응답 이벤트도 새로 확정 처리하지 않는다. 주차 후 현재 연결·요청·취소 상태를 확인해 필요한 응답을 적용하되, 미확인 메시지나 승인을 자동 전송하지 않는다. 내비의 이미 진행 중인 요청 결과와 취소 기록까지 버리는 것은 아니다. 해당 결과는 상태와 대조해 처리한다.

내비 안내가 시작되면 음성을 멈추거나 줄이고, 다시 이야기할지는 사용자가 고를 수 있게 한다. 발표용 예시 대사는 다음과 같다.

> **내 에이전트:** “길 안내 먼저 들을게. 대화는 잠깐 쉬어가자.”

**주행 중 음성 대화 목표 장면 · WF-051**

차량이 주행으로 바뀌어도 검증된 `driving_voice`라면 P02의 상대 캐릭터 음성 문답만 이어가는 안이다. 검증되지 않았거나 플랫폼이 막으면 WF-032 blocked로 전환한다. 현재 목업에서는 아래를 주차/발표용 준비 음성으로 재현한다.

> **A:** “솔바람은 어떤 여행을 좋아해?”
>
> **상대 캐릭터:** “공개한 소개를 보면, 바다를 천천히 걷는 걸 좋아하는 편이에요.”
>
> **A:** “잠깐 쉬자.”
>
> **상대 캐릭터:** “좋아요. 대화는 쉬어갈게요.”

공개 취향이 없으면 “지금 소개된 정보만으로는 잘 모르겠어요”로 바꾼다. 실제 STT가 없으면 A 대사는 녹음/대본으로만 제공하며 마이크 수집·자유 해석 성공으로 표시하지 않는다. 목록 선택·메시지 전달·통화 시작·만남/경로 승인·B 이벤트·이야기 시간 전환은 잠금 상태를 유지한다. 큰 캐릭터·긴 자막 없이 발화자와 짧은 상태만 표시하고, 시각 표시도 허용되지 않으면 음성만 가능한지 별도 검증한다. ‘주행 중’이라는 이유만으로 검증된 음성까지 막는 기준과 플랫폼 blocked를 혼동하지 않는다.

실제 오디오 포커스와 통화 종료·일시 중단 동작은 04번에서 구현·검증할 범위만 기록한다. 시연자 전환만으로 실제 차량 신호 연동을 완료했다고 설명하지 않는다.

이벤트는 해당 장면·요청·회차에 한 번만 적용한다. 중복·다른 요청·취소되거나 종료된 연결·이전 회차의 늦은 응답은 무시한다. 회차·버전·요청을 구분하는 구체적인 방법은 04번에서 정한다.

최종 선택 재시연은 같은 이야기에서 다른 결말만 보여주는 기능이다. 앞선 공개 프로필·연결·대화·만남 기록과 승인된 설정은 유지하고 내비 요청을 반복하지 않는다. 이미 선택한 함께 결말이 다음 회차의 결과에 남지 않게 한다. 실제 사용자에게 상대 연결을 되살리는 기능으로 제공하지 않는다.

여기서 유지는 표시용 이야기 참조를 뜻한다. 현재 철회한 공개 승인·종료한 연결을 과거 값으로 되돌리지 않고, 재시연의 최종 선택은 유효한 checkpoint와 새 finalRound로 검증한다. 현재 내비·제한·복구 상태도 유지한다.

전체 초기화는 앱 상태와 외부 내비 상태를 구분한다. 시험 경로의 경유지·목적지를 정리하고 확인하기 전에는 새 실제 연동 시연 준비가 끝난 것으로 표시하지 않는다. 정리 절차와 실패 시 복구 방법은 04번, 완료 증빙은 05번에 둔다.

## 9. 소재·검수·후속 문서 연결

### 9.1. 준비할 소재

- **캐릭터·장면:** A 선택용 외형, B 외형, C·D 요약 카드, 발화자 표시, 온보딩 소개 미리보기, 가상 카페·해변·만남 재연, 선택적 장식 전후.
- **대사·자막:** S01 문답·요약·소개, S02 여행 정리, S03 추천, S06 Q1·Q2와 내 친구 대화, S07 M1·M2·R1·R2, S08 일반 통화, S09 장소 제안, S10 실제 만남 재연, S11·S12 두 결말, 8절 예외 안내. S08-MC·S13은 추가 묶음으로 분리한다.
- **음성:** 에이전트 소개·답변·전달 안내, B 메시지 낭독, 통화 샘플, 만남 재연, 두 결말을 문장 단위로 준비한다. B 메시지는 직접 인용하고 발화자 표시를 유지한다. A 별명 변경이 녹음과 충돌하지 않게 한다. 음성 없이도 자막으로 진행할 수 있어야 한다.
- **데이터:** 2절의 인물·후보·양쪽 일정·장소·이동 수치, 본인이 확인한 소개값·공개 승인·표현 프리셋을 한 묶음으로 관리한다. 자유 입력 원문은 본인 웹·서버에만 보존하고 상대 공개 프로필·차량 전달본에서 제외한다.
- **발표 상태:** 대본·시연 음성·이동 개념 시연·실제 SDK 결과·모의 내비를 구분해 표시한다. 앱의 사용자 대사에 기술 설명을 섞지 않는다.

### 9.2. 대본 검수 기준

1. S01의 관심사와 승인한 표현이 소개·추천·차량·내 캐릭터 결말까지 일치한다. 수정·비공개 처리한 항목을 뒤에서 다시 공개하지 않는다.
2. S06은 공개 프로필 기반 캐릭터 답변, S07은 확인·전송한 사용자 메시지와 B 답변이다. 두 장면의 발화자·이벤트·대기 상태를 혼동하지 않는다.
3. S06~S08의 순서를 바꾸거나 일부를 건너뛰어도 연결을 유지하고 만남을 제안받을 수 있다. 콘텐츠 이용 자체로 다른 동의가 생기지 않는다.
4. 일반 통화·MC 참여·만남·내비 승인·최종 동행을 각각 구분한다. 상대 또는 요청이 바뀌면 이전 동의를 재사용하지 않는다.
5. 양쪽 일정 데이터가 01번과 일치하고, A 화면에 B의 전체 개인 일정이 공개되지 않는다. 시험 좌표의 실제 경로를 시연값의 계산 근거로 사용하지 않는다.
6. S10에서 캐릭터의 확인된 소개 표현과 B의 실제 만남 대사가 연결된다. 그 효과를 검증된 사실로 설명하지 않는다.
7. S12-B에는 온보딩을 기억하는 친구 대화와 다음 활동이 있다. 단순 일정 안내·실패 화면으로 끝내지 않고, A의 선택과 B의 선택에 맞는 안내를 사용한다.
8. 이전 회차·취소된 요청의 늦은 응답이 새 시연·다른 결말·취소된 만남을 되살리지 않는다. 주행 제한 복귀 후에도 자동 전송·승인하지 않는다.
9. 내비 추가·제거 실패와 모의 진행을 구분한다. 실제 연동과 외부 경로 초기화는 증빙이 있는 범위만 완료로 표시한다.
