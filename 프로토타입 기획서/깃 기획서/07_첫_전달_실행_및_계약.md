# 첫 웹·차량 전달 실행 및 계약

작성일 2026년 11월 11일 · 버전 0.2 · 구현 범위 `handoff-my-trip-v1` · API schemaVersion 2

## 0. 목표 설계와 현재 실행의 차이

01~05 v0.6·08 v0.2의 목표는 **자유 입력 채팅이 기본, 예시는 초안 보조**다. 이 문서의 현재 `handoff-my-trip-v1`·schemaVersion 2 실행은 이전 preset 입력 기반으로 남아 있으며 자유 입력 저장/대화 화면·주행 음성을 아직 구현하지 않았다. 아래 지원 명령·JSON Schema·8종 명령의 실제 동작을 목표 설계처럼 고쳐 읽지 않는다.

다음 구현은 목표 schemaVersion 3에서 ONBOARDING_ANSWER의 answerText/inputSource·원문 보존·별도 소개값 확인을 지원해야 한다. v2 서버에 자유 입력을 preset으로 바꿔 보내지 않는다. 지원 capability/버전이 다르면 초안을 보존하고 버전 미지원 안내를 표시하며, schema·서버·웹·차량 소비자를 함께 갱신해 검수한다. v2 상태 파일을 v3로 자동 변환하거나 기존 preset으로 원문을 복원했다고 하지 않는다. 새 v3 시연 상태와 이전 기록을 분리하는 마이그레이션 정책을 구현 PR에 명시한다.

현재 Manifest에는 DO·STT 연동이 없고 제한 관측은 Boolean 잠금이다. 주행 음성 목표 `driving_voice`는 구현·검증 전이며, 문서 수정으로 현재 실제 제한 차단을 해제하지 않는다. 실제 음성 제공은 04번 7.3절·05번 V05의 지원 증빙과 기능별 제한 검증 후에만 가능하다. 담당자·마감은 미정이다.

## 1. 구현한 범위

웹에서 별명·캐릭터(a-01/a-02)·말투(calm/light_humor)·지원 여행 취향을 선택하고, 본인 여행용 비공개 프로필과 강릉 고정 계획을 저장한다. 차량은 최신 전달본을 실제 HTTP로 받아 표시하고 현재 세션·전달 ID·참조 버전으로 ACK한다. **서버에 ACK를 저장한 뒤에만 웹이 차량 수신 확인을 표시한다.**

이번 화면은 [03](03_화면_및_상호작용_설계서.md)의 전체 M01~M04 대화 경험보다 작은 통합 진입점이다. 상대 연결·공개 소개·AI 대화·음성·내비 SDK·O01·업무 초기화·두 결말은 구현 전이다. 05의 W01~W05 전체 완료로 표시하지 않는다. 전체 계약 의미는 [04](04_개발_및_연동_명세서.md)를 유지한다.

여행 날짜 2026-11-14는 시연 이야기 날짜이며 개발 마감이 아니다. 여행 시간·목적지는 명세의 고정 preset이고 임의 일정 입력 기능은 없다.

## 2. 실행

저장소 루트에서 웹·서버 터미널을 연다.

```sh
cd mock-app
nvm use
npm ci --ignore-scripts
npm start
```

nvm 미사용자는 Node 22.22.2를 선택한 뒤 실행한다. [웹](http://127.0.0.1:3000)에 접속해 **프로필과 여행 저장 → 차량에 전달 준비**를 누른다. 저장 성공은 단계별 명령 영수증으로 확인하며 중간 실패 시 이전 단계는 남을 수 있다. 다시 확인해 저장을 마친다.

차량은 [차량 실행 안내](../mock-app/vehicle/README.md)로 `mockDebug`를 설치·실행한다. 정차 상태에서 **내 여행 불러오기**를 누른다. 차량에서 선택한 별명·캐릭터·말투·취향·일정이 일치하고 웹이 수신 확인으로 바뀌어야 한다.

서버 주소는 Mac `127.0.0.1:3000`, Android Emulator `10.0.2.2:3000`이다. loopback 전용이며 CORS·LAN 공개·운영 인증은 제공하지 않는다. Android 평문 HTTP 허용은 debug의 `10.0.2.2`만 지정한다. release는 해당 설정을 포함하지 않는다.

## 3. 계약과 지원 API

[JSON Schema](../mock-app/shared/contracts/handoff-v2.schema.json)의 `$defs`와 [wire 예제](../mock-app/shared/examples/index.json)가 실제 구현의 필드 기준이다. SERVER가 계약을 변경하면 WEB·CAR의 enum/필드 매핑도 함께 검토한다. Node/웹은 `shared/config/protocol.mjs`, Android는 `DemoApi`·`JourneyParser`·`HandoffRepository`가 소비한다.

| API | 역할·동작 |
|---|---|
| `GET /health` | 역할 불필요. schemaVersion·storeId·status·scope |
| `GET /api/scenario` | web/car별 지원 preset·capabilities. 연결·내비·operator는 false |
| `GET /api/state?view=web\|car` | `X-Demo-Actor`와 view 일치. 현재 표시·허용 행동 |
| `GET /api/handoff` | car 전용. 최신 my_trip snapshot. 조회는 ACK 아님 |
| `GET /api/commands/{commandId}?runId=...` | 같은 역할·클라이언트의 영수증. `applied` 또는 `not_found` |
| `POST /api/commands` | schema·역할·회차·버전·도메인 조건을 검증해 저장 |

web은 `X-Demo-Client-Id` UUID를 브라우저 localStorage에 유지한다. 첫 web 저장이 이 시연 파일의 소유 클라이언트를 고정한다. 다른 브라우저는 본인 정보와 변경 행동을 받지 않는다. 이는 로컬 시연 식별이며 인증 기능은 아니다.

지원 명령은 ONBOARDING_ANSWER, PROFILE_CONFIRM, PROFILE_PRIVATE, TRIP_SAVE, HANDOFF_PREPARE, CAR_SESSION_OPEN, CAR_STATUS, CAR_LOADED의 8종이다. 이 범위 target은 `{}`이며 HANDOFF_PREPARE는 `mode:my_trip`, TRIP_SAVE는 `presetId:gangneung-01`·`shareSummaryApproved:false`만 지원한다. 4개 질문의 확인된 preset으로만 summary를 파생한다.

프로필·계획 변경은 전달본과 ACK를 무효화한다. 같은 원본의 준비 재확인은 전달 ID를 유지한다. 차량 ACK는 최신 handoffId·handoffVersion·sourceVersions·mode·vehicleSessionId를 모두 검사한다. `peer`는 항상 null이다.

## 4. 영수증·저장·제한

단일 큐에서 (runId, actor, commandId) 중복을 버전 검사보다 먼저 조회한다. 동일 봉투 재전송은 이전 영수증과 현재 projection을 반환한다. 같은 ID의 본문 변경·새 명령의 이전 version은 거절한다. CAR_STATUS는 현재 세션과 증가 seq를 검증하는 사실 보고이므로 이전 업무 version도 허용한다.

웹과 차량은 사용자 명령 봉투를 전송 전 로컬에 보존한다. 타임아웃 후 영수증과 현재 상태를 읽고, `not_found`이면 미확인으로 유지한다. **사용자가 다시 전송할 때만 같은 ID·본문**을 보낸다. 정상 실패 응답은 종료된 요청으로 처리한다. 차량 상태 heartbeat는 새로운 관측값·증가 seq로 보고하며 오래된 제한 관측을 재전송하지 않는다.

`runtime/state.json`에 상태와 영수증을 함께 쓰고 임시 파일 fsync → rename → 디렉터리 fsync가 성공한 후 메모리를 확정한다. 교체 전 실패는 500 STORE_FAILED, 교체 후 결과 불확실은 503 UNAVAILABLE로 쓰기를 중단한다. 재시작은 파일·영수증 무결성을 검증하고 이전 프로세스의 차량 제한 허용을 폐기한다. 손상 파일을 새 기본값으로 덮지 않는다.

실제 `CarUxRestrictionsManager` 현재값·리스너를 사용한다. 미확인·제한·화면 비활성은 로컬에서 즉시 잠그고 서버도 fresh 상태와 허용 행동을 검사한다. 500ms 간격의 요청은 겹치지 않으며 2초간 보고가 없으면 서버가 제한 확인을 만료시키고 version을 올린다. 서버 재시작·화면 복귀 시 새 제한 관측 전에는 ACK할 수 없다.

Pleos Connect 2.1.0 이미지의 차량 API는 `/apex/com.android.car.framework/javalib/android.car-module.jar` 부팅 경로에 있었다. 컴파일은 `useLibrary("android.car")`, Manifest의 `android.car` shared library는 optional로 선언해 해당 이미지에 설치하고 현재값/콜백을 확인했다. 기어 그림이나 속도로 제한을 추정하지 않는다. [공식 주행 규제 가이드](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/driving-restriction-development-guide)

## 5. 저장 파일 운영

정상 종료는 서버 터미널의 Ctrl+C를 사용한다. lock은 같은 파일을 두 프로세스가 쓰는 것을 막는다. 강제 종료로 `runtime/state.json.lock`이 남으면 기록된 PID가 종료됐고 같은 저장 경로를 쓰는 프로세스가 없음을 먼저 확인한 뒤 lock만 정리한다. 실행 중에는 제거하지 않는다.

다른 브라우저로 새 시연이 필요하면 서버를 정상 종료하고 기존 state.json을 별도 백업 경로로 옮긴 뒤 재시작한다. 이는 개발자의 수동 새 저장소 준비이며 앱 내 RESET 흐름 구현은 아니다. 시연 중 상태·영수증을 삭제하거나 편집하지 않는다. 브라우저 pending 요청도 기존 회차의 결과를 확인한 뒤 정리한다.

현재 영수증은 자동 삭제하지 않으므로 장시간 운영과 다중 사용자 서비스에는 별도 DB·인증·보존 정책이 필요하다. runtime·브라우저 확인 파일은 Git에서 제외한다.

## 6. 확인 결과와 후속 작업

2026-11-11 Mac / Pleos Connect 2.1.0 API 34에서 확인했다.

- 자동 검증 27개: 공통 예제, 실제 HTTP 저장/전달/ACK·재시작, 중복·버전·동시성, 역할·클라이언트·출처, 제한·만료, 원본 변경, 저장 장애·손상, 웹 응답 유실·재시도.
- Android mock APK 빌드와 Lint 성공. 오류 0개, 버전 업데이트·백업·SharedPreferences KTX 권고 경고 14개.
- Playwright 브라우저에서 ‘구름여행 · 햇살 친구 · 가벼운 유머 · 카페’ 저장 → 실제 Pleos 표시 → 웹 수신 확인.
- 웹에서 별명·캐릭터·말투·취향을 다시 저장하면 이전 전달 확인이 해제되고, 새 전달본을 별도로 불러와 확인한다.
- 실제 제한 확인 known=true/restricted=false, 설정 앱 전환 후 foreground=false·허용 행동 없음, 복귀 후 재확인.
- CLI의 차량 제한 강제 전환은 이미지가 non-user build를 요구해 수행하지 못했다. 제한 활성·미확인·만료의 서버 차단은 자동 검증으로 확인했다. 실제 주행 제한 전환은 Virtual Console 또는 지원 이미지에서 추가 검증한다.

첫 연결은 SERVER 계약·저장, WEB 준비·복구, CAR-UI 표시, CAR-PLATFORM 전송·제한의 인계 기준이다. 이후 역할별로 M01 대화 화면, 상대 연결/공개 조건, 음성, 별도 real 내비 검증, O01·RESET을 확장한다. 개발 인원·담당 배정은 여전히 미정이다.
