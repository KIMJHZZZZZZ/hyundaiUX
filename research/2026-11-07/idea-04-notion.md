## ⑤ 핵심 시나리오 — 내 차가 15분 동안 심해 관측실이 된다

<b>페르소나와 욕구.</b> 32세 직장인 지윤은 퇴근 후 주 1회 정도 외부에서 충전하며 혼자 머무를 시간이 있다. 이 빈도는 검증할 페르소나 가정이다. 지윤이 원하는 것은 충전 시간을 없애는 것이 아니라, 누구에게도 맞추지 않고 짧은 이야기에 몰입했다가 끝맺는 경험이다. 한 회차는 15분을 기본 실험값으로 삼는다. 실제 충전 예상시간을 항상 알 수 있다고 가정하지 않고 본인이 10·15·20분 중 선택한다. 앱 이름은 <b>캐빈 퀘스트</b>, 첫 에피소드는 직접 제작한 ‘심해 관측실의 마지막 신호’다.

| 단계 | 구체적인 사용자 행동·대사 | 시스템과 AI가 실제로 하는 일 | 사용자가 얻는 가치·예외 |
| --- | --- | --- | --- |
| 주차 직후 0\~1분 | 충전을 시작한 뒤 ‘혼자, 15분, 긴장감 낮게’를 고른다. | CarUxRestrictions로 실행 가능 여부를 먼저 확인한다. Vehicle State의 충전 신호가 지원되면 상태만 읽는다. 충전 잔여시간을 얻지 못하면 자동 추정하지 않는다. | 설정 세 가지로 시작한다. 충전 중이어도 시스템 제한이 걸리면 실행하지 않는다. 신호대기·정체는 사용 상황이 아니다. |
| 1\~3분, 입장 | 차 스피커에서 파도와 안내 음성이 들린다. ‘지윤 관측원님, 탐사 기록을 복구해 주세요.’ 실제 이름 대신 선택한 별명을 쓴다. | 차 화면에는 단서 1개와 두 가지 선택만 보여 준다. 차를 실제 잠수함으로 제어하지 않는다. 소리·서사·정적인 시각 요소로 공간을 해석한다. | 평소의 운전 공간을 개인 극장처럼 느끼는 첫 장면이다. 공조·조명·시트 제어가 없어도 성립해야 한다. |
| 3\~6분, 첫 선택 | 사용자가 ‘무전기를 먼저 확인할래’라고 말하거나 버튼을 누른다. | 입력을 <code>choice_id</code> 후보로 정규화한다. 사건 그래프의 현재 장면에서 허용된 선택인지 코드로 확인한다. LLM은 무전 담당 NPC의 응답과 짧은 연결 문장을 생성한다. | 선택이 다음 대사에 반영된다. 모호한 음성은 임의 선택하지 않고 두 선택지를 재제시한다. |
| 6\~9분, 개인화 | 지윤이 ‘좀 더 편안하게 해줘’라고 요청한다. | 긴장도 설정을 낮추고 허용된 사운드·문체로 바꾼다. 얼굴·심박·표정으로 감정을 추론하지 않는다. 핵심 단서와 정답은 바꾸지 않는다. | 감정 분석 없이도 취향을 반영한다. AI가 사건을 즉흥적으로 뒤집어 진행 불가능해지는 문제를 줄인다. |
| 9\~11분, 체류시간 변화 | 약속 상대가 일찍 도착해 ‘3분 안에 끝내줘’를 누른다. | 남은 노드 중 필수 단서와 결말만 남기는 결정적 규칙으로 단축 경로를 고른다. LLM은 이미 공개된 사실에 맞춰 연결 대사를 만든다. | 영상 재생의 단순 중단과 달리 짧은 완결감을 준다. ‘정확히 3분’은 측정 목표이지 검증된 보장이 아니다. |
| 11\~13분, 엔딩 | 사용자는 신호의 출처를 골라 관측 임무를 마친다. | 정해진 결말 중 사용자 선택과 일치하는 하나를 재생한다. 평가가 필요하면 선택 기록을 사용하며 성격·지능 점수를 만들어 내지 않는다. | 누가 더 잘했는지 경쟁하지 않고 자신이 만든 결말을 얻는다. |
| 종료 | ‘다음 회차 기억하기’ 또는 ‘기록 없이 종료’를 고른다. | 기본은 로컬 진행 상태만 보관한다. 서버 음성 원본은 기본 저장하지 않는다. 클라우드 이어하기는 별도 선택이다. | 차를 공유해도 개인 취향이나 대사가 다음 운전자에게 자동 노출되지 않는다. |
| 어느 시점이든 출차·전화·통신 단절 | D 전환 또는 시스템 제한, 전화 수신, 네트워크 끊김이 발생한다. | 제한 시 화면·입력·게임 오디오를 즉시 중단하고 체크포인트 저장. 포커스 상실 시 재생 중단. 통신 장애에는 검수된 로컬 대사로 진행하거나 일시정지. | 안전 조건을 LLM에게 판단시키지 않는다. 다시 주차해도 자동 재생하지 않고 재개 선택을 받는다. |

<b>두 사람으로 확장할 때</b>는 앞좌석·뒷좌석 센서가 누가 말했는지 알려준다고 가정하지 않는다. 각자가 모바일 웹에서 별명을 선택해 자기 턴에 입력한다. 스마트폰은 입력 수단이고 이야기·소리는 차량에서 공유한다. 첫 MVP는 한 명의 완결 경험을 먼저 검증한다.

<b>경쟁을 이기는 가설은 ‘AI가 이야기를 만든다’가 아니다.</b> 휴대폰 오디오북은 접근성이 좋고 콘텐츠가 풍부하다. 유튜브·OTT는 이미 익숙하다. 캐빈 퀘스트는 ① 사용자가 정한 체류시간 안에서 마무리하는 사건 구조, ② 차의 객실을 무대로 느끼게 하는 사운드 연출, ③ 전화·출차로 끊겨도 선택과 단서를 유지하는 이어하기의 조합을 검증한다. 이 세 가지가 일반 스마트폰 경험보다 좋아지지 않으면 차량특화성이 부족한 것이다.

이번 조사로 <b>주차 공간 이용 행동</b>은 확인했으나 <b>캐빈 퀘스트 재사용·지불 의사</b>는 확인하지 못했다. 공모전에는 이 구분을 그대로 제시한다. 기존 연구의 ‘미래 차량이 거실·사무실이 된다’ 수치는 원문에서 61/62%가 혼재해 대표 수치로 쓰지 않는다.

## ⑦ 구체적인 구현 파이프라인

| 계층 | 입력과 처리 | 출력·실패 처리 |
| --- | --- | --- |
| 차량 상태 어댑터 | AAOS 주행 제한, Vehicle State 지원 여부와 충전 상태를 읽는다. 앱 시작·복귀·재연결 때 상태를 재조회한다. | 상태 미확인·제한 활성은 잠금. 충전 상태 미지원이면 수동 15분 선택으로 진행하며 ‘충전 연동’이라고 표시하지 않는다. |
| 세션 계획기 | 사용자가 선택한 시간, 인원, 긴장도와 제작자가 작성한 사건 그래프를 받는다. | <code>session_id</code>, <code>scene_id</code>, 필수 단서, 허용 선택, 남은 시간 예산을 생성한다. 실제 충전 완료시간을 LLM으로 예측하지 않는다. |
| LLM 서버 | 현재 장면, 이미 확정된 사실, 사용자 발화, 허용 응답 길이만 보낸다. API 키는 차량 APK에 넣지 않는다. | <code>scene_id</code>, <code>npc_line</code>, <code>choice_ids</code>, <code>fact_ids</code>, <code>duration_hint_sec</code> 형태의 구조화 응답. 실제 스키마는 구현 시 정의한다. |
| 검증기 | JSON 형식, 존재하는 ID, 금지 주제, 단서 일관성, 길이 제한을 확인한다. | 잘못된 장면 이동·미등록 선택은 거부. 재시도 1회 후 사전 대사로 대체한다. LLM이 만든 외부 URL이나 실행 명령을 수행하지 않는다. |
| 사건 엔진 | 정해진 상태 전이표로 선택을 적용한다. 긴급 종료 요청에는 단축 결말 경로를 사용한다. | 일관된 결말·체크포인트. 주행 상태 판단·권한 판단과 완전히 분리한다. |
| 음성·화면 출력 | 검증된 텍스트를 재생한다. Pleos TTS 제공 여부가 불확실하므로 데모는 사전 녹음과 승인 가능한 외부 음성 서비스 어댑터를 준비한다. | 오디오 포커스를 얻었을 때만 재생. 동적 음성 연결이 안 되면 실제 LLM 텍스트와 사전 음성의 범위를 시연 화면에 구분한다. |
| 기록 | 세션별 가명 ID와 선택·오류·완주 여부를 저장한다. | 원시 발화의 장기 저장은 기본 꺼짐. 삭제·프로필 전환·세션 만료를 제공한다. |

<b>Gleo 연동 후보 3개:</b> <code>START_CABIN_SESSION</code>, <code>CHANGE_SESSION</code>, <code>STOP_SESSION</code>. 두 번째 액션은 더 짧게·더 편안하게·재개 등을 명시적 enum으로 받는 설계안이다. 실제 App Schema와 검토 승인이 필요하다. Gleo는 앱 기능을 호출하는 입구이고, 장면 응답을 생성하는 범용 LLM은 앱의 별도 서버에 둔다. 기능 이름·인자는 본 기획의 제안이며 공식 제공 API 이름이 아니다.

<b>현재·조건부·미래의 구분:</b> 주차 UI, 사건 그래프, 별도 LLM, 체크포인트는 자체 개발 범위다. Vehicle State와 AAOS 연결은 문서상 경로가 있으나 실제 계정·에뮬레이터로 확인해야 한다. Gleo는 승인 조건부다. 차량 조명·공조·시트·다채널 좌석별 음향은 MVP 의존성에서 제외한다. 향후 공개·승인된 제어 범위에서만 별도 추가한다.

## ⑧ MVP, 수요 검증, 사업성과 확장

<b>11월 13일 내부 MVP 목표:</b> 에피소드 1개, 10·15분 두 길이, 분기 3개, 엔딩 2개, 주행 잠금, 포커스 중단, 네트워크 대체, 진행 저장을 만든다. 캐릭터 무한 생성·멀티플레이·음성 복제·하드웨어 제어는 제외한다. 30초 시연은 ‘15분 시작 → 내 선택으로 NPC 반응 변화 → 3분으로 단축 → 시스템 제한으로 즉시 중단 → 주차 후 재개’를 보여 준다. 시간 압축 장면은 시연 편집임을 표시한다.

<b>선정 전 실험:</b> 정기적으로 차 안에서 10분 이상 기다리는 성인 12명을 모집하는 탐색 실험을 제안한다. 대표성 있는 설문이 아니다. 같은 장소에서 같은 스피커로 10분 오디오북과 10분 캐빈 퀘스트를 순서를 교차해 사용하게 한다. 진행자는 ‘차 안 게임을 원하느냐’고 먼저 유도하지 않고 최근 실제 대기 경험을 묻는다.

- 관찰 지표: 자발적 완주, 중간 종료 사유, 다시 실행 선택, 단축 엔딩 성공, 수동 개입 횟수, 질문 때문에 휴식을 방해받았는지.
- 사전 의사결정 기준 제안: 12명 중 7명 이상이 다음 대기 때 직접 재실행을 선택하고, 8명 이상이 체험을 끝내며, 최소 6명이 ‘휴대폰 오디오북과 다른 차 안 경험’을 자기 말로 설명하면 추가 실험으로 진행한다. 성과 예측이나 통계적 유의성 기준이 아니다.
- 중단·전환: 절반 이상이 상호작용을 끄거나 오디오북을 선택하면 자유 질문을 줄여 수동 청취형으로 전환한다. 이를 ‘실패한 고객’으로 해석하지 않는다.
- 기술 통과 조건: 주행 제한·초기 상태 미확인·재연결·포커스 상실·잘못된 JSON·타임아웃 상황에서 출력이 안전하게 멈추거나 로컬 대체되는지 에뮬레이터로 확인한다. 실제 지연시간과 오디오 품질은 측정해 제출한다.

<b>사업 가설:</b> 기본 에피소드 무료, 장르별 에피소드 팩 또는 자동차 브랜드·콘텐츠 IP 공동 제작이 후보다. ‘구독을 원한다’는 근거는 없다. 1회 팩 2,900원과 월 4,900원은 인터뷰용 가격 가설이며 실제 판매가·시장 적정가격이 아니다. 검증된 이용횟수가 낮으면 월 구독 대신 개별 구매가 맞을 수 있다. 콘텐츠 제작·검수비와 음성 합성·LLM 호출비, 파트너 수익배분을 회차당 공헌이익으로 계산해야 한다.

월간 활성 차량 수는 <b>도달 가능한 대상 차량 수 × 설치 전환율 × 월간 1회 이상 이용 비율</b>로 산정한다. 예시로 1,000대 × 20% × 40% = 80 활성 차량/월이다. 이는 세 입력을 임의로 둔 시나리오 계산이며 시장 전망이 아니다. ‘사람 MAU’와 ‘활성 차량 수’를 섞지 않는다. 4주 재방문은 첫 체험 차량 중 4주 안에 다시 실행한 차량 비율로 정의하고 실측 전에는 숫자를 제시하지 않는다.

<b>확장 단계:</b> 1) 혼자 주차 10\~15분 → 2) 커플·친구 2인 협동 → 3) 가족·관광 IP 에피소드 → 4) 차종별 승인된 사운드·조명 연출 → 5) 규제와 플랫폼이 허용하는 미래 자율주행 객실 경험. L2/L3라는 명칭만으로 운전자에게 게임을 허용하지 않는다. 미래 가치는 ‘자율주행이 되면 자동으로 사용자가 늘어난다’가 아니라, 제작한 사건·세션 엔진을 더 긴 체류시간과 여러 탑승자에게 재사용할 수 있다는 데 있다.
