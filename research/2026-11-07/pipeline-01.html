모든 단계에 우선하는 안전 게이트

문서 확인

CarUxRestrictions가 최종 기준입니다. 차량의 주차 상태와 플랫폼 UX 허용을 모두 확인한 뒤 세션을 시작합니다.

초기·신호 끊김 → 잠금알 수 없는 상태를 허용으로 해석하지 않습니다.
제한 활성 → 전부 중단세션·오디오·화면 상호작용을 멈추고 게임·참여 UI를 숨깁니다.
신호 대기 ≠ 주차(P)속도 0만으로 시작하거나 자동 재개하지 않습니다.

주차 확인 후에도 사용자의 명시 재개가 필요합니다. 주행용 가족 게임 승인을 전제하지 않습니다.

입력에서 경험까지

위에서 아래로 진행 · 안전 상태 변화는 어느 단계에서든 우선 처리

  1. 1

    가족과 주차 모드 선택

    설계안

    가족 참여 여부와 주차 상태를 먼저 확인합니다. 운전자는 주행 중 참여하지 않습니다.

  2. 2

    익명 역할 · 시간 정하기

    설계안

    이름 대신 역할을 선택하고 세션 길이를 10분 또는 15분으로 정합니다.

  3. 3

    입력 어댑터

    승인 필요

    Gleo 승인 시 음성 명령을 연결합니다. 미승인 시 터치 또는 동승자 모바일 웹을 사용합니다.

  4. 4

    세션 상태 머신 · 발언 턴

    설계안

    대기 → 질문 → 발언 → 다음 턴 → 종료. 발언 순서와 타이머는 앱이 관리합니다.

  5. 5

    별도 LLM → 구조화 JSON

    설계안

    허용 소재와 동의한 발언 요약만 전달합니다. 다음 질문·짧은 진행 멘트·대화 챕터를 제안합니다.

  6. 6

    검증 → 오디오와 가족 대화

    설계안

    콘텐츠·길이·현재 턴을 검증한 뒤 재생합니다. 음성 출력 미지원 시 사전 제작 오디오를 사용합니다.

  7. 7

    명시적으로 저장

    설계안

    사용자가 저장을 선택한 요약만 보관합니다. 원음은 기본 저장하지 않습니다.

Gleo 입력 어댑터

승인 필요

App Schema 검토 승인 후 연결합니다. 아래는 앱이 정의할 명령 3개이며 플랫폼 API 이름이 아닙니다.

  1. 세션 시작하기
  2. 다음 대화로 넘어가기
  3. 세션 끝내기

미승인 대체: 터치 또는 모바일 웹 입력을 같은 세션 로직으로 전달합니다.

현재 문서: actionCalls 최대 3개. Gleo가 앱 기능을 호출하며 앱이 결과를 반환합니다.

Gleo ≠ 앱의 생성 AI

대화 소재와 진행 멘트 생성만 담당합니다. 발언 턴·타이머·저장 여부·차량 상태는 앱이 결정합니다.

별도 LLM 백엔드는 앱의 설계안입니다. Gleo의 범용 생성 API 공개를 가정하지 않습니다.

네트워크 단절

설계안

미리 만든 대화 카드와 진행 오디오로 이어갑니다. 진행 상태는 로컬에 유지합니다.

시연에서 구분할 것

모의

음성 입력 대신 샘플 발언 요약을 넣는 경우 화면에 모의 입력으로 표시합니다.

경험의 초점

기존 창밖동화와 구분: 지역 정보 전달보다 가족의 발언 균형과 서로의 이야기 듣기에 집중합니다.

오디오 포커스 상실 → 재생 중단

전화·안전 안내·Gleo 등으로 포커스를 잃으면 즉시 멈춥니다. 포커스 회복만으로 자동 재생하지 않고 안전 게이트를 다시 확인합니다.

지원 확인과 앱 권한 승인

문서 존재는 계정 권한·차종 지원·실차 배포 보장이 아닙니다. TTS/STT·위치·차량 제어는 실제 제공 상태를 확인하고 미지원 기능은 대체 경로로 전환합니다.

문서 확인공식 문서의 인터페이스·정책설계안이 앱의 제안 아키텍처승인 필요권한·스키마·실제 제공 상태 확인모의시연용 데이터·대체 입력
