## 2. 이번 서비스에서 유지해야 할 결정

아래 내용은 현재 전달된 Notion 댓글과 사용자 요청을 기준으로 한 제품 요구사항이다. 공식 Pleos 정책과 혼동하지 않는다.

- 앱명은 **말문이 트립!**이다. AI 친구 서비스가 아니라, 각자 여행하는 **실제 사람끼리의 익명 음성 교류**가 중심이다. AI MC는 첫 질문·대화 시작을 돕는 보조 역할이다.
- 최초 설문에서 **음성만 이용 / 음성 후 공개 장소 만남도 검토** 선호를 선택한다. 만남 동의는 필수가 아니며, 음성만으로 끝나도 정상적인 성공 경험이다.
- 만남 선호 선택, 후보 수락, 마이크 연결, 공개 장소 만남 동의, 경유지 반영은 서로 다른 결정이다. 한 번의 체크를 모든 동의로 재사용하지 않는다.
- **실제 만남이 성사되더라도 여행이 끝날 때까지 실명·연락처·최종 목적지를 공개하지 않는다.** 여행 종료 시에도 자동 공개하지 않는 설계가 요구사항과 충돌하지 않으며, 별도 합의가 없으면 이를 기본값으로 한다.
- 상대에게 공개할 정보는 회차별 별명, 관심 주제, 교류 방식, 대화 가능 상태 등으로 제한한다. 운영 서버가 재매칭 방지·신고에 쓸 내부 식별자와 상대에게 보이는 식별자는 분리한다.
- 정확한 현재 위치, 목적지명, 상세 경로, 차량번호, 차량 ID, 정확한 출발·도착 시간은 매칭 카드·음성 자막·지도·푸시·기록에서 유출하지 않는다. 대략적인 방향도 인구가 적은 구간에서 재식별 위험이 있으므로 선택적 최소 정보로 다룬다.
- 성별 필터는 합의가 확정되지 않았다. MVP 기본 설문에서는 제외하고, 필요 시 **후속 검증 가설**로 명시한다. 남녀 구분·이성 연결을 이미 정한 제품 정책처럼 쓰지 않는다.
- 익명 앱 온보딩 벤치마크의 사실·이 서비스 적용안·미검증 가설을 구분한다. 보조 평가 점수는 내부 판단 도구이며, 공식 제출 양식의 점수나 당선 보증으로 제시하지 않는다.

### ‘여행 종료’와 ‘만남 종료’의 상태 정의

`음성 연결 종료`, `공개 장소 만남 종료`, `내 여행 종료`는 서로 다른 상태다. 공개 장소에서 헤어졌다고 내 최종 목적지·연락처를 열어서는 안 된다. 여행 종료 판단은 사용자의 명시적 종료 등 검증 가능한 조건으로 정의하고, 미확인·앱 강제 종료·연결 유실을 정보 공개 조건으로 쓰지 않는다. 익명성은 데이터 처리 범위에 관한 약속이며, 육성·외모를 통해 상대가 자발적으로 인지하는 사실까지 완전히 차단한다고 표현하지 않는다.

## 3. 공식 Pleos 화면 기준: 확인된 사실과 설계용 수치

### 시스템 영역과 앱 영역

Pleos 공식 화면은 Status bar, Driving view, GNB, Application window로 구성된다. 주행 정보·상태·공조·앱 독은 앱이 새로 만드는 기능이 아니다. 시스템 패널과 키보드가 앱 위에 겹칠 수 있다. 앱 시안은 시스템 문맥을 보여주되, 구현 범위는 오른쪽 앱 창으로 명확히 표시한다. [공식 Display Layout](https://document.pleos.ai/docs/connect/guide/docs-design/getting-started/layout)

사용자가 제공한 넓은 화면 이미지와 현재 시안은 **왼쪽 주행 정보 + 오른쪽 큰 앱 창 + 하단 공조·독**의 Standard형 문맥으로 설명하는 것이 적절하다. 가로로 긴 모든 이미지를 Connect-W 제품 사양이라고 부르지 않는다. 공식 도식에는 Standard 17·14.6·12.9인치, Wide 24.6인치 및 Waterfall 18.5인치가 보이며, 구형 Connect-L은 현재 본문에서 Connect-S로 재분류되었다. [공식 화면 유형 및 도식](https://document.pleos.ai/docs/connect/guide/docs-design/getting-started/layout#%ED%99%94%EB%A9%B4-%EC%9C%A0%ED%98%95)

Standard 창은 두 앱의 1:1 또는 한 앱의 2:0 구성, Wide 창은 2:1 또는 1:2 구성을 지원한다. 앱을 항상 차량 전체 화면에 고정하는 전제는 피한다. [공식 Window Policy](https://document.pleos.ai/docs/connect/guide/docs-design/getting-started/window)

### 픽셀·dp·세이프존에 관한 판정

1. 확인한 공식 HTML 본문과 `displaylayout_03.svg`는 **고정 앱 해상도를 1280dp·1920×1080px라고 규정하지 않는다**. SVG의 `viewBox=8907×8800`은 설명용 인포그래픽 캔버스이며 차량 디스플레이 해상도가 아니다.
2. 현재 시안의 1920×1080px는 **제안서용 설계 아트보드**다. `screen_manifest.json`의 앱 창 `x=572, y=76, w=1300, h=851` 또한 시안 좌표다. 공식 SDK 해상도·안전 영역이라고 쓰면 안 된다.
3. 실제 개발은 대상 Emulator/차량에서 window 크기, 시스템 insets, density를 확인하고 dp 기준으로 재검증해야 한다. 제출 시에는 ‘Pleos 시스템 구성을 참고한 UI 시안·모의 데이터, 실제 창 크기·밀도는 Emulator 검증’이라고 설명한다.
4. Status bar 문서의 **40dp safe bounds**는 SP0/SP1 시스템 아이콘 영역을 구분하는 내부 right padding이다. 앱의 상하좌우 안전 여백 40dp로 일반화하지 않는다. [공식 Status bar](https://document.pleos.ai/docs/connect/guide/docs-design/components/status-bar)
5. GNB의 공조·내비·즐겨찾기·앱 라이브러리는 시스템 소유 영역이다. 앱 종료·신고·다음 버튼을 하단 시스템 독에 넣지 않는다. [공식 GNB](https://document.pleos.ai/docs/connect/guide/docs-design/components/gnb)

### 읽기·터치·방향 대응

- Pleos는 짧게 알아볼 수 있는 정보, 한 손 조작, 과도한 움직임 억제를 요구한다. 대비 4.5:1 이상, 중요 정보 5mm·보조 정보 3mm 이상 등의 지침이 있다. 한국어를 ‘120자까지 가능’으로 자동 환산하지 않는다. 야간에는 밝기·대비를 조절한다. [공식 UI Design Guide](https://document.pleos.ai/docs/connect/guide/docs-design/Introduction/intro)
- 공식 버튼 본문은 상태·구조를 설명하며 치수는 별도 SVG에 들어 있다. 본 검토에서는 `basic_size.svg`의 수치를 판독하지 못했으므로 **48px를 Pleos 공식 최소값이라고 쓰지 않는다**. [공식 Basic button](https://document.pleos.ai/docs/connect/guide/docs-design/components/actions/basic-button)
- 보조 검증 기준으로 Google의 차량용 UI 지침은 터치 영역 최소 76×76dp, 가능하면 영역 간 23dp를 제시한다. 이를 채택하면 **Google 보조 기준에 따른 설계 목표**라고 출처를 구분한다. px 크기의 screenshot만으로 dp 준수를 주장하지 않는다. [Google 차량용 Visual principles](https://developers.google.com/cars/design/design-foundations/visual-principles)
- Portrait·landscape 창을 각각 설계하고 크기 변경 시 핵심 기능을 보존해야 한다. 세로 창에서는 주제·상태·종료를 우선하고 보조 설명·지도는 접는다. 백그라운드 진입·복귀·프로세스 재생성 시 세션 상태를 복원한다. [공식 앱 구조 및 동작 모델](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/app-structure-screen-model)

## 4. 주행 안전과 플랫폼 승인에서 빠지면 안 되는 조건

**음성 통화라는 이유만으로 주행 중 허용된다고 단정하면 안 된다.** Social/Communication은 공식 앱 카테고리지만, 해당 문서에서 주행 중 제한적 허용 가능 예시를 든 카테고리는 Music/Audio·Maps/Navigation·Mobility Services다. 서비스의 주된 목적에 따라 카테고리를 정하고 허용 여부를 검증해야 하며, 음성 통신을 Music/Audio로 임의 포장하지 않는다. [공식 앱 카테고리](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/app-category)

주행 중 사용 가능 여부는 `CarUxRestrictions`, 지역, 플랫폼 버전, 차량 사양, DO 선언과 심사를 함께 확인해야 한다. DO 미선언 앱의 기본 동작은 주차 사용 가능·주행 사용 불가다. 일시적으로 속도 0이 되었다는 이유만으로 주차용 설문·설정·만남 동의를 열지 않는다. 현재 S14의 ‘주행 시 연결 중단·잠금, 주차 상태 확인 후 재개’는 보수적인 MVP 정책과 잘 맞는다. [공식 지역별 주행 규제 정책](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driving-restiction-policy)

설문·로그인·긴 규칙·후보 탐색·공개 장소 선택·신고 상세 작성은 주차 중 처리한다. 규제 변경은 화면뿐 아니라 마이크·실시간 채널·대기 세션에도 적용하고, 주행 진입 직전에 수락/연결 요청을 보낸 경쟁 상태까지 테스트한다. 내비 안내·차량 경고·전화의 오디오 우선권에 반응해야 한다. [공식 주행 안전 설계](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline)

| S12 | 선택적 만남 동의 | 양쪽 최초 선호+현재 개별 동의 확인, 거절한 이유 상대 비공개, 만남 거절로 대화 경험 불이익 없음 |
| S13 | 공개 경유지 제안 | 공공 장소만, 양쪽 확인, 본인 내비에만 추가, 최종 목적지 불공개, 우회부담, 취소 |
| S14 | 주행 제한 | 상태 전환을 명확히 안내, 통신/마이크 처리, 주차 시 재개, 복잡한 조작·자동 재연결 금지 |
| S15 | 조건 변경·재확인 | 지연·경로 변경·주차 후 재개 시 양쪽 재확인, 취소해도 안전하게 내 여행 지속 |
| S16 | 공개 장소 도착 | 상대 실시간 핀·번호판 대신 일회성 약속 코드, 유효기간·실패·오인 확인 경로 |
| S17 | 만남 종료 | 만남 종료와 여행 종료 구분, 이후 자동 추적·개인정보 공개 없음, 경유지 유지/제거 영향 안내 |
| S18 | 마무리 설문 | 만족도·불편 경험, 건너뛰기, 상대에게 응답이 전달되지 않음, 신고는 별도 경로 |
| S19 | 매칭 없음 | 시간 초과·조건 미충족, 조건 수정·다음 주차 때 재시도·종료, 가짜 사람·가짜 인원수 금지 |
| S20 | 종료·차단·신고 | 먼저 연결을 끊을 수 있음, 긴 상세 입력은 주차 후, 접수/네트워크 실패, 재매칭 금지 적용 |

### 설문 데이터 사전

필수 설문은 교류 방식·가능 시간·관심 주제로 작게 시작하고, 가명/공개 범위를 확인한다. 말의 양, 피하고 싶은 화제, 조용한 대화 선호 등은 선택 확장 항목으로 두되 이미 수집한 것처럼 매칭 설명에 쓰지 않는다. 성별·실명·사진·세부 목적지·직장·집 주소는 초기 익명 프로필에 넣지 않는다. 성인 확인을 실제로 구현하기 전에는 ‘성인 확인 완료’가 서버가 검증한 실사용 상태라는 오해를 주지 않도록 시안·예시임을 명시한다.

### 실패·취소·안전 분기

- 매칭 취소와 후보 거절은 마이크 연결 전에 즉시 완료된다. 후보 유효시간 만료 후 수락 요청은 실패 상태로 돌리고 자동 대체 연결하지 않는다.
- 네트워크 유실·상대 이탈·권한 거부·오디오 포커스 상실은 각각 구분한다. 재접속 중에 마이크를 몰래 다시 켜지 않는다.
- 내비가 없거나 위치/경로 접근 권한이 없으면 익명 음성 기능을 가능한 범위에서 제공하고 공개 경유지 추천은 비활성화한다.
- 상대의 정확한 ETA를 실시간 숫자로 표시하지 않는다. 공개 장소 만남에 필요한 약속 시간대는 양쪽 동의 후 제한적으로 공유하되, 최종 목적지 도착 시각·출발지·전체 동선을 유추할 상세 자료를 제공하지 않는다.
- 장소 합의 전에는 실제 POI를 상대 위치와 결부해 보여주지 않는다. 장소 합의 뒤에도 양쪽 차량의 실시간 핀·이동 궤적·주차면·차량 색/번호는 공개하지 않는다.
- 안전상 종료·차단은 상호 동의 없이 가능하다. 상세 신고 작성 완료가 통신 종료의 선행 조건이어서는 안 된다.

## 6. 현재 산출물에 대한 확인과 남은 핵심 공백

`output/2026-11-08_말문이트립/assets/screen_manifest.json`에서 S01~S20의 `overflow=false`를 확인했다. 이는 생성 단계의 영역 검사 결과이며 실제 Pleos 실기기 적합성, 접근성, 터치 크기, 버튼 동작 검증을 대체하지 않는다. S05 개인정보 화면과 S14 주행 제한 화면을 이미지로 확인했다. S05는 공개·비공개 구분과 가명 프로필이 명확하며, S14는 운전 중 대화를 멈추는 정책을 분명히 전달한다. 전체 화면의 차량 정보는 ‘가상 차량 화면’, 상단은 ‘UI 시안·모의 데이터’라고 표시되어 있다.

제출 전 우선 확인할 공백은 다음과 같다.

1. **카테고리·DO 승인**: 주행 중 익명 소셜 음성 허용을 확정 기능처럼 약속하지 않는다. MVP 주차 모드와 후속 검증 범위를 문서·화면·개발 일정 전체에서 일치시킨다.
2. **실제 인증과 가명성**: 실제 인증 정보는 운영용, 상대 공개 정보는 회차별 가명으로 구분한다. 외부 인증 제공자·저장 범위·미성년자 접근 정책은 확정 전 검증 과제로 둔다.
3. **음성 처리**: AI MC가 원음 전체를 상시 청취·분석하는지, 이용자 선택으로 질문만 생성하는지 확정한다. 기본 녹음 없음과 신고 증거 확보를 동시에 주장한다면 기술적 충돌을 설명해야 한다. 신고 처리용 최소 메타데이터와 원음 저장은 별개다.
4. **여행 종료 상태**: 만남 종료만으로 개인정보 공개가 발생하지 않는 서버 상태 전이를 명세한다. 종료 시에도 자동 공개하지 않는 기본값을 문서에 명확히 둔다.
5. **정확 위치 간접 유출**: 공개 장소 추천·우회 시간·대화 가능 시간·ETA·경로 조건을 조합해 최종 목적지나 위치를 추정할 수 있는지 확인한다. ‘연락처를 숨김’만으로 익명성이 완성되지 않는다.
6. **반응형 실증**: 현재 20장은 가로 시안이다. 세로 앱 창 1개와 야간 모드 최소 1장을 후속 검증 대상으로 명시한다. 실제 dp·insets·밀도는 Emulator에서 확인한다.
7. **연결 밀도**: 공개 POI·회차·시간대 등 작은 실증 범위에서 매칭 성공률과 대기 시간을 먼저 검증한다. 이용자가 없을 때의 S19를 운영 정책과 연결한다.
8. **성과 수치**: MAU·Retention은 검증 전 목표/가정으로 쓰고, ‘등록 수=MAU’, ‘만남 수=성공’으로 바꾸지 않는다. 음성 전용 만족과 안전한 거절·종료도 가치 지표다.

보안·개인정보 처리의 공식 원칙은 위치·음성·계정 요구 목적 고지, 불필요한 개인정보 미저장, 로그 마스킹, 차량/사용자 ID의 가명화, 운전자 교체 시 세션 관리다. 이 원칙을 각 화면 문구뿐 아니라 백엔드·로그·삭제 정책에 반영해야 한다. [공식 보안·개인정보 설계](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/security-privacy)

## 7. 최종 작성자가 바로 쓸 수 있는 주석 문구

> 화면은 Pleos Connect의 시스템 구성을 참고한 UI 설계 시안이며 차량·상대 프로필·수치는 모의 데이터입니다. 실제 앱 창의 크기·밀도·시스템 여백과 주행 제한은 Emulator 및 대상 차량에서 검증합니다. MVP는 주차 상태에서 이용하며, 주행 중 음성 기능 확대는 앱 카테고리·DO·지역 정책 검증 이후 판단합니다.

> 사용자의 실명·연락처·정확한 현재 위치·최종 목적지는 상대에게 공개하지 않습니다. 공개 장소에서 만나더라도 전체 여행이 끝날 때까지 이 원칙을 유지하며, 여행 종료 후에도 자동 공개하지 않습니다. 장소 만남은 양쪽이 각각 동의한 경우에만 검토하고, 누구나 즉시 중단할 수 있습니다.
