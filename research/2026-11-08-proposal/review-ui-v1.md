# 말문이 트립! 최종 UI 검수 v1

검토일: 2026-11-08. 검토자는 원본 이미지를 직접 확인하고 DOCX XML 및 생성 소스를 대조했다. 이 검토는 **제안 UI 이미지와 문서 구조에 한정**하며 SDK 실행·실기 터치·음성 연결·Word 페이지 배치를 검증한 결과가 아니다.

## 판정

**검토 범위 내 통과. 제출을 막는 UI 겹침·잘림·한국어 오탈자·익명성 규칙 충돌을 발견하지 않았다.** 비차단 캡션 표현 1건은 아래에 기록했다. Word PDF에서의 페이지 나눔·그림 축소·줄바꿈은 root의 페이지 PNG 검수 결과를 따라야 한다.

## 흐름·규칙 일치 확인

- `build_proposal.py`의 13개 `pairs`와 manifest 26개 ID가 일치한다. 문서 설명은 S01~S11을 음성 전용 기본 경로, S04B·S12~S17을 만남 선호를 선택한 별도 예시로 구분한다. S03의 음성 전용 선택과 S12의 만남 선택은 동일 세션의 상태 오류로 제시되어 있지 않다.
- 설문은 교류 방식→시간·주제→공개 범위로 이어지고, 선택형 만남 시간·장소 선호는 S04B로 분리되어 있다. 성별 필터·실명·사진을 요구하는 설문이 추가되지 않았다.
- S05B는 내비 이용 동의 거절 시 직접 권역 선택을 제공한다. S06B는 마이크 권한을 대화 동의와 구분하고 거절 선택을 제공한다. S08은 상호 수락 뒤 연결함을 밝힌다.
- S09는 AI의 첫 질문과 두 사람 대화를 구분한다. S10에는 마이크 켜짐·음소거·즉시 종료·중단 및 신고가 보인다. 사람 간 대화를 AI 대화로 표현하지 않는다.
- S11은 실제 만남 없이 정상 종료할 수 있게 하며, 여행 후 개인정보 자동 공개도 부정한다.
- S12의 만남 의사, S13의 구체 장소·시간 동의, S13B의 약속 확정과 본인 내비 요청이 분리되어 있다. 확정 전 장소는 ‘제안 단계’로 표시된다.
- S14는 주행 중 음성 송수신 중지·마이크 꺼짐·주차 후 직접 재개를 표시한다. S15는 현재 주차 중임을 밝히고 약속 유지·취소를 다시 제공한다.
- S16·S16B는 공개 장소와 일회성 확인용 코드·약속 시간을 사용하고, 차량번호·실명·최종 목적지를 표시하지 않는다. S16B에는 즉시 종료·신고 경로가 있다.
- S17의 만남 종료와 S21의 내 여행 종료가 구분된다. S21은 기존 방 접근·새 연결 요청을 닫고 다음 여행에 새 별명을 쓰며, 종료 후에도 개인정보가 자동 공개되지 않음을 명시한다.
- S19는 가짜 이용자 수·매칭 보장을 표시하지 않고 종료·조건 수정 선택을 제공한다. S20은 연결 종료·차단을 먼저 완료한 뒤 신고 또는 종료만 하기를 선택하게 한다.
- 페르소나 두 이미지는 주차·휴식 문맥이며 실제 참가자 정보·번호판·연락처를 포함하지 않는다. 가상 인물임을 이미지 픽셀에 직접 인쇄하지는 않았으나 DOCX의 인접 캡션과 대체텍스트 모두 **AI 생성 가상 인물**과 조사 결과가 아님을 명시한다.
- 좁은 앱 창은 실제 태블릿 전체를 세로로 돌린 이미지가 아니라 앱 창만의 한 열 배치다. 선택 카드·설명·버튼이 겹치지 않는다. 시안·모의 데이터·SDK 화면 아님을 하단에 표시한다.

## DOCX XML에서 확인한 범위

대상: `output/2026-11-08_말문이트립/말문이_트립_02_서비스_기획서.docx` v1.

- 원본 문서에서 이어받은 최상위 제목 스타일 ID `1`은 정확히 6개이며, 제목은 `1 앱 한 줄 소개`, `2 기획 배경`, `3 앱 주요 기능 및 차량 특화 요소`, `4 주요 사용 시나리오`, `5 개발 계획`, `6 기대효과 및 발전 가능성`이다.
- 01 참가신청서·03 개인정보 동의서·04 서명란 본문은 포함하지 않는다. 서명·참가자 연락처를 가상으로 작성한 부분이 없다. 이 생략은 02 작성본을 만드는 의도된 범위다.
- 그림 33개와 `word/media/` 이미지 33개가 있으며, **33개 모두 `wp:docPr/@descr` 대체텍스트가 있다**.
- 두 페르소나의 대체텍스트는 각각 AI 생성 가상 인물·실제 인터뷰나 이용자가 아님을 명시한다. 26개 앱 창 이미지 캡션은 모든 화면이 제안 시안임을 밝힌다.
- 공식 Window Policy 그림은 자체 실행 화면과 구분하는 캡션과 T20 출처 연결이 있다. 전체 자체 시안은 시스템 문맥의 재구성, 우측 앱 창이 개발 범위, 모의 데이터, APK 실행 아님을 명시한다.
- 전체 이미지의 2560×1440 출력 크기는 실제 앱 창 크기나 dp 보장으로 쓰지 않는다. 본문에도 window·density 실측과 dp 재검증을 구분하는 설명이 있다.
- 구조도는 본 패스 중 SDK 검토 의견을 반영해 업데이트되었다. 현재 외부 `architecture.png`는 ‘자체 매칭 서버는 정밀 목적지 미수집’과 ‘앱은 자체 매칭 서버와 상대에게 정확한 목적지를 보내지 않음’으로 범위를 좁혔다. **v1 DOCX의 기존 임베디드 그림은 root의 v2 재빌드에서 교체되어야 한다.** 이 교체는 root에게 전달했다.

## 발견한 구체 항목

### 비차단 · 좁은 앱 창 캡션의 ‘종료’ 설명

- 위치: `build_proposal.py`의 `responsive_portrait.png` 캡션(그림 6).
- 현 문구: ‘주요 선택과 종료를 한 열로 유지하는 제안’.
- 관찰: 실제 그림은 S03 교류 방식 선택 화면이며 하단 동작은 **이전 / 다음**이다. 종료 기능을 이 그림에서 보여주지는 않는다.
- 최소 수정: ‘주요 선택과 다음 동작을 한 열로 유지하는 제안’ 또는 ‘선택 카드와 주요 버튼을 한 열로 유지하는 제안’으로 캡션만 바꾸면 그림과 정확히 일치한다. UI 자산 수정은 필요하지 않다.

## 이번 검토에서 하지 않은 것

Word에서 렌더된 모든 PDF 페이지, 최종 DOCX v2 이미지 교체, 실제 클릭·키보드·접근성 트리, 터치 영역의 dp, 야간 모드, 실제 기기의 주행 규제·음성·내비 동작은 검증하지 않았다. 이미지 관찰 통과를 이 항목의 통과로 확대 해석하지 않는다.
